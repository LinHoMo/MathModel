## 四、项目定位（已锁定，不可偏离）

### 4.1 核心定位

> **MathModel 是一个面向数学建模的 LLM-free、可复现、可审计的建模能力实验基础设施。**
> 核心目标是将数学建模过程结构化、标准化、可视化并可验证。
> 它让外部 Agent 负责实际认知与模型构造，由 Harness 负责冻结问题、记录建模过程、建立模型与证据的可追溯关系、验证执行真实性并进行能力测量。
> 第一阶段以数学建模竞赛为受控实验场，最终将同一套 Model Representation 与 Measurement Infrastructure 扩展到科研论文中的具体数学建模问题。

### 4.2 三分法（核心名词定义）

| 名词 | 定位 | 回答的问题 |
|------|------|-----------|
| **Model Construction** | 核心能力对象 (What) | Agent 能不能把现实问题构造成一个正确、完整、自洽、可求解、可验证的数学模型？ |
| **Model Representation** | 核心标准化对象 (How) | 一个数学模型应该如何被机器和人结构化表达？（Model IR / Model Graph / Model Card / Model Trace） |
| **Harness** | 核心可信度对象 (How do we know) | 我们怎么证明这个模型确实由 Agent 构造出来？怎么证明测量没有被伪造？怎么复现？怎么定位失败？ |

### 4.3 不可违反的铁律

1. **项目只做 Harness**（LLM-free 的 workflow/工具/验证/证据/测量层），认知工作由外部 Agent（Doubao/GPT/人）在 harness 下完成
2. **绝不在 core 内构建 LLM 执行器**或把项目做成完整数模 Agent
3. **标准化的是表达/接口/证据，而非答案**（ODE/状态空间/递推/PDE 都可进同一 Harness）
4. **先定 Model IR 再推进 P15**——暂停 P15.1→P15.2 机械推进
5. **核心对象是 Model Construction**，不是"能力"或"论文生成"
6. **"有依有据"为核心哲学**：Problem→Assumption→Variable→Model→Experiment→Evidence→Claim 完整可反向追溯链
7. **不修改 v3.1.x core architecture**（除非发现真实 core bug，且需 minimal patch + regression）
