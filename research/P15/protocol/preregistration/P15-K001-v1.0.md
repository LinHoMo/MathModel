## 0. 一句话

> 外显的 Modeling Knowledge 是否增加 LLM 的**数学模型构造能力**（而非方法名命中率）？
> 用 2×2 因子设计（Knowledge × Case）+ Sham 负控制，在 blocked / paired 单位上做多重复，
> 盲评 Model Construction Quality，报告效应量与置信区间。

---

## 1. 研究问题与假设

| # | 问题 | 对应统计量 |
|---|---|---|
| **RQ1** | Knowledge 是否有主效应？ | `mean(B,D) − mean(A,C)` |
| **RQ2** | Case 是否有主效应？ | `mean(C,D) − mean(A,B)` |
| **RQ3** | Knowledge × Case 是否存在交互？ | `(D − B) − (C − A)` |
| **RQ4** | Knowledge 是否改变 failure mode 分布？ | FM 命中分布的逐条对比 |
| **RQ5** | Knowledge 提升的是**模型结构质量**还是仅方法命中率？ | `L2 composite` vs `method_family identification` 的效应对比 |
| **RQ6** | 效应是否跨题型泛化？ | 主检验 3 题 + 泛化观察 2 题的分层报告 |

### 预注册假设（双侧，不做方向性承诺）

- **H1（主）**：Knowledge 主效应 ≠ 0。
- **H2**：Case 主效应 ≠ 0。
- **H3**：交互项 ≠ 0。
- **H0-Sham**：`B − E = 0`（若 B ≈ E，则「知识有效」的替代解释是「更多上下文」而非「正确知识」）。

### 四种可能结论（预先声明，避免事后叙事）

| 结果形态 | 解释 |
|---|---|
| `A ≈ B ≈ C ≈ D` | LLM 内化知识已足够，外显知识无增益 → 停止扩卡 |
| `A < B ≈ C < D` | Knowledge / Case 独立贡献且协同 |
| `A < B, C ≈ A` | 抽象建模知识比案例更重要 |
| `A ≈ B < C ≈ D` | 经验案例比显式知识更重要 |
| `A < B, D ≈ B` | 案例无额外增益，知识本身已足够 |

## 2. 实验设计

### 2.1 条件（2×2 + Sham）

| 臂 | Knowledge | Case | 注入内容 | 角色 |
|---|---|---|---|---|
| **A** | 0 | 0 | 题面 only | 基线 |
| **B** | 1 | 0 | 题面 + 冻结方法卡全文 | Knowledge 单独 |
| **C** | 0 | 1 | 题面 + 结构案例 | Case 单独 |
| **D** | 1 | 1 | 题面 + 方法卡 + 结构案例 | 双因子 |
| **E** | sham | 0 | 题面 + **等长但机理错位**的方法卡 | **负控制，不入主假设检验** |

**为什么必须 2×2**：三臂（A/B/C）无法测出 C（Case-only）自身效应，也无法估计交互。
**为什么必须 Sham**：`B > A` 可能只是「prompt 更长 → 思考更充分」。E 臂分离「正确知识」与「更多文本」。

### 2.2 实验单位与区组

```
Problem  = block（区组）
Condition = treatment（A/B/C/D/E）
Replication = stochastic repeat（seed 42 / 43 / 44）
```

**统计比较的是同一道题在不同 condition 下的配对差**，不是跨题裸均值相减。
题目难度差异被 block 吸收，不进入处理效应。

### 2.3 规模

| 用途 | 题 | 条件 | 重复 | runs |
|---|---|---|---|---|
| **主检验** | 2020_B / 2018_A / 2019_C | 5 | 3 | **45** |
| **泛化观察**（单列报告，不入主检验） | 2022_C / 2024_A | 5 | 1 | **10** |
| 合计 | | | | **55** |

- 主检验三题各有专属方法卡（mc-dp / mc-numerical-pde / mc-queuing-theory），构成 in-catalog 区组。
- 2022_C（统计分类，无专属卡）与 2024_A（多体动力学/几何，out_of_catalog）用于观察效应是否跨家族，
  **其数据单独列表，不与主检验合并计算 p 值**。
- 规模下调规则：若 Batch 0 实测单次生成耗时使 55 runs 不可完成，可退到主检验 2 重复（30 runs），
  **但必须在报告中声明，且不得同时改动指标或阈值**。

### 2.4 随机化

`k001_gen_bundles.py` 以 `seed=42` 对每个 problem 内的 5 个条件做 shuffle，写入
`frozen_specs/run_order.json`。执行严格按表顺序推进，**禁止**按 A→B→C→D→E 的固定顺序跑，
以削弱 cache effect / provider drift / 执行者状态漂移。

### 2.5 冻结项（condition 必须是唯一实验变量）

| 冻结项 | 载体 |
|---|---|
| 题面 | `frozen_specs/problem_set.yaml`（含 `input_sha256`） |
| 知识集 | `frozen_specs/knowledge_set.yaml`（card_id + `card_sha256`） |
| 案例集 | `frozen_specs/case_set.yaml`（路径 + `sha256`） |
| Sham 集 | `frozen_specs/sham_set.yaml`（错位映射） |
| prompt | `frozen_specs/prompt_templates/{A,B,C,D,E}.md`（`prompt_sha256`） |
| 顺序 | `frozen_specs/run_order.json` |
| 生成器 | `generator_provider` / `generator_model` / `agent_identity` |
| 产物契约 | `MODEL_IR v1.0`（`artifact_schema_version`） |
| 评分器 | rubric `MODEL_CONSTRUCTION_RUBRIC.md` v1.0 + `evaluator_model` |
| 分析 | `frozen_specs/analysis_plan.md` + `analysis/scripts/paired_analysis.py` 的 sha256 |

运行期若任一项 hash 漂移 → `k001_freeze.py --check` FAIL → 实验作废重跑。
**FROZEN 之后改任何冻结项 = new revision（v1.1），不得原地修改。**

## 3. 资产

### 3.1 冻结知识集（每题 1 张目标卡，注入全文不裁剪）

| 题 | 目标卡 | 家族 |
|---|---|---|
| 2020_B | `mc-dp` | dynamic_programming |
| 2018_A | `mc-numerical-pde` | numerical PDE |
| 2019_C | `mc-queuing-theory` | queueing |
| 2022_C | `mc-kmeans` | unsupervised / clustering（retriever top-1，非人工指定） |
| 2024_A | `mc-ga` | metaheuristics（retriever top-1；**out_of_catalog，弱匹配**，仅作泛化观察） |

> 2022_C / 2024_A 的目标卡**不是人工指定**，而是 `knowledge.py recommend` 的 top-1
> （实际执行：`--types classification` → `mc-kmeans`；`--types optimization` → `mc-ga`）。
> 这样可同时观察「自动检索能否提供相关知识」，但因其非人工校准，这两题不进主假设检验。

### 3.2 Sham 构造（循环错位）

| 题 | Sham 卡 | 与目标机理的关系 |
|---|---|---|
| 2020_B | `mc-queuing-theory` | 无关（离散序贯 vs 随机服务） |
| 2018_A | `mc-dp` | 无关（连续场 vs 序贯决策） |
| 2019_C | `mc-numerical-pde` | 无关（排队 vs 热传导） |
| 2022_C | `mc-arima` | 同族相邻但机理不符（时序 vs 横截面分类） |
| 2024_A | `mc-queuing-theory` | 无关（几何运动 vs 排队） |

要求：格式/量级/字段结构与目标卡一致；注入 token 数记录在 manifest，作为协变量检查。

### 3.3 案例资产（分层，杜绝答案泄漏）

- **structural case**（本轮注入 C/D 臂）：题面 → 建模思路、变量/约束/目标骨架、机理选择理由与候选对比、常见坑。
  **不含**数值解、不含完整公式推导、不含 `gt.json` 中的答案常量。
- **solution case**（本轮建库不注入）：完整建模与求解，留作后续 `K+C+S` 臂扩展。

**泄漏门禁**：`k001_leak_scan.py` 逐份扫描 structural case ——
命中 `gt.json` 的 `acceptable_solution_variants` 答案常量 / final answer / ≥3 个 gt 数值常量 → FAIL，
不得进入 bundle。第一轮**只注入 structural case**，以确保测的是「从案例中学结构」而非「从案例中抄答案」。

## 4. 评价指标

### 4.1 Primary Endpoint：Model Construction Quality

**预先声明主终点 = L2 composite（structure + mathematics），不是 method_selection。**

```
MCQ_primary = (L2.1 + L2.2 + L2.4 + L2.5 + L2.6 + L2.7) / 13 × 100
```

| 分量 | 组成 | 满分 |
|---|---|---|
| structure | L2.1 变量完备 + L2.2 参数完备 + L2.7 方程结构完整 | 6 |
| mathematics | L2.4 目标正确 + L2.5 约束完备 + L2.6 机理正确（权重 3） | 7 |

（`L2.3 假设合理性` 计入 secondary，不进主终点。）

### 4.2 Primary Vector（每个 Model Artifact 输出 6 维向量，不只总分）

```
M = [alignment, structure, mathematics, consistency, validation, support]
```

| 分量 | 定义 | 计算方式 |
|---|---|---|
| alignment | 问题理解与子问题对齐 | `(L1.1+L1.2+L1.3+L1.4+L1.5)/9 × 100` |
| structure | 变量/参数/方程结构 | `(L2.1+L2.2+L2.7)/6 × 100` |
| mathematics | 目标/约束/机理 | `(L2.4+L2.5+L2.6)/7 × 100` |
| consistency | 符号-声明自洽 | 机器判定：`100×(1 − 未声明符号率) − 20×索引不一致标记`，clamp `[0,100]` |
| validation | 验证充分性 | `(L4.1+L4.2+L4.3+L4.4+L4.5)/9 × 100` |
| support | 主张-证据支撑率 | 机器判定：`supported_claims / total_claims × 100` |

向量化的目的：能分辨「Knowledge 只提升 structure 不提升 mathematics」这类结构性发现，
而总分 `62 → 71` 无法提供这种信息。

### 4.3 Secondary / Tertiary

- **Secondary**：L1 / L3 / L4 分层分、validation quality、sensitivity quality、FM 命中分布（RQ4）
- **Tertiary**：`method_family identification`（对照 `allowed_model_families`，机器判定）、
  knowledge utilization 率、`token_cost`、`latency_seconds`

> **RQ5 的判定方法**：比较 Knowledge 主效应在 `MCQ_primary` 上与在
> `method_family identification` 上的大小。若前者显著而后者不显著（或反之），
> 即可回答「知识是让人更会建模，还是更会说方法名」。

### 5.2 单 run 流程

## 6. 盲评协议

### 6.1 去标识

`k001_blind_pack.py` 导出盲评包：

```json
{ "submission_id": "<UUID4>", "problem_statement": "...", "model_ir": {...} }
```

**剥离**一切 condition / arm / knowledge / batch 标签。condition 只存在于
`experiments/P15-K001/key/condition_map.json`，在 `ANALYSIS` 阶段才解封。
文件名、目录名、JSON 内部字段均不得出现 `A`/`B`/`C`/`D`/`E`/`sham`/`knowledge` 等字样。

### 6.2 Generator ≠ Evaluator

- **Generator**：`agent_identity`（外部 agent，手工范式）
- **Evaluator**：**必须与 generator 不同的模型**（本地 `opencode` / `claude` CLI 指定另一模型），
  按 `MODEL_CONSTRUCTION_RUBRIC.md` v1.0 逐维打分
- 评分落 `analysis/raw/scores/<sid>.json`，含 `evaluator_model` 字段

### 6.3 人工抽样

用户对 **≥20%（≥11 份，覆盖全部 5 个条件）** 抽样复核，报告 Cohen's κ（分维）/ ICC（合成分）。

### 6.4 声明的限制

> **生成侧无法盲**：手工范式下执行 agent 必然看到是否注入了知识卡，无法对其隐藏 condition。
> 真正起作用的盲是**评分区盲**（evaluator 看不到 condition）。
> 此限制在此显式声明，且不得以「生成侧盲」为由来主张因果强度。

## 7. 分析计划（先冻结，后看数据）

### 7.1 冻结顺序（防 HARKing）

```
RUNNING → VALIDATION → DATA FREEZE（analysis/raw → analysis/frozen 快照 + sha256）
        → ANALYSIS FREEZE（paired_analysis.py sha256 写入 analysis_plan.md）
        → 统计分析 → 报告
```

**DATA FREEZE 之后不得改动评分；ANALYSIS FREEZE 之后不得改动分析脚本。**

### 7.2 统计方法（`analysis/scripts/paired_analysis.py`，零第三方依赖）

1. 逐题对 rep 求均值 → 得到 `problem × condition` 的 5 元均值向量
2. 逐题计算：
   - `Δ_K(p) = mean(B,D) − mean(A,C)`
   - `Δ_C(p) = mean(C,D) − mean(A,B)`
   - `Δ_I(p) = (D − B) − (C − A)`
   - `Δ_Sham(p) = B − E`（robustness）
3. 跨题聚合：取 3 个 block 的均值作为点估计
4. **区间估计**：cluster bootstrap（对 problem 重采样，10 000 次，seed=42）→ 95% 百分位 CI；
   同时报告 rep 级 bootstrap 与逐题配对差
5. **显著性（次要）**：符号置换检验 / Wilcoxon 符号秩

### 7.3 功效的诚实声明

主检验 block 数 **= 3**，符号置换的最小可达 p 值为 `2 × (1/2)^3 = 0.25`（双侧 0.125）。
因此：

> **本轮以效应量 + 95% CI 为主结论，p 值仅作辅助参考。**
> 跨题型的强泛化结论留给第二轮（12–20 题）再下。

### 7.4 决策门（evidence-driven roadmap）

```
Δ_K 的 95% CI 下界 > 0
   ├─ 是 → 进入 Phase C：知识组件消融（mechanism / formulation / applicability / validation / failure memory）
   └─ 否 → 记录为 negative result，回头查知识质量，不进 P15.2

Δ_Sham 的 CI 跨 0 且点估计 ≈ Δ_K
   └─ 说明效应来自「更多上下文」而非「正确知识」→ 协议需重设计（加长但空的填充控制）
```

**不做**「P15.1 跑完自动进 P15.2」的流水线式推进。
