## 0. 一句话

> 区分 **Agent 能力** 与 **Runtime 增益**：同一个 Constructor 在
> 有/无 LinHoMo Runtime 闭环（执行→fidelity→验证→修订）下，
> 产出可执行数学模型的构造质量是否不同？

## 1. 研究问题与假设

| # | 问题 | 对应统计量 |
|---|---|---|
| **RQ1** | Runtime 闭环是否带来构造质量主效应？ | `mean(+RT) − mean(−RT)`（Constructor 内配对） |
| **RQ2** | Constructor 类型是否解释更多方差？ | `η²(Constructor)` vs `η²(Runtime)` |
| **RQ3** | Runtime 增益是否依赖 Constructor 类型（交互）？ | `(ΔRT_Ci)` 逐 Constructor 对比 |
| **RQ4** | 机械指标（fidelity/exec success/validation pass）是否复现盲评结论？ | 盲评 vs 机械指标的相关 |

预注册假设（双侧，不做方向性承诺）：
- **H1（主）**: Runtime 主效应 ≠ 0。
- **H2**: Constructor 主效应 ≠ 0（预期存在——不同 Agent 能力不同）。
- **H3**: Runtime × Constructor 交互 ≠ 0（Runtime 增益对弱 Constructor 更大）。
- **H0-机械**: 盲评 MCQ 与机械指标（fidelity 等）相关 ≤ 0.3（若成立，
  机械指标优先——盲评不可信，延续 P2-2 发现）。

## 2. 设计

**4 Constructor × 2 Runtime 条件 × 8 题 × 2 seeds = 64 runs**

| Constructor | 说明 | capability |
|---|---|---|
| `ref` | Reference Constructor（LLM-free，规则模板 + 方法卡） | C2-C3 |
| `mma` | MathModelAgent Adapter（外部 Agent 集成，见 P1-1 协议） | C5（外部） |
| `gen` | 通用 LLM 直接构造（无 Runtime 语义约束） | C2-C3 |
| `lin` | 自研基线（K003 最优配方 S+V 条件同款提示） | C3-C4 |

Runtime 条件：
- `−RT`：Constructor 产出 MODEL_IR + code 即止（静态评估）。
- `+RT`：注入 LinHoMo Runtime——真实 subprocess 执行 → fidelity →
  数值验证 → 失败则 Revision 循环（≤2 轮）→ 终态 MODEL_IR。

**8 题**：2011_B / 2017_B / 2018_A / 2018_B / 2019_C / 2020_B /
2022_C / 2024_A（与 K003 同题集，保证维度可比）。

**主终点**：
1. **MCQ_primary**：盲评 Model Construction Quality（22 维 rubric，
   与 K001/K002/K003 同 rubric，报告 L1/L2/L3/L4 分组与 composite）。
2. **VAL_mech**（机械）：execution success rate、fidelity_score、
   validation pass rate、revision 轮数、M1→M2 修正成功率。

## 3. 实验流程

```
每 run:
  Constructor.construct(problem, context=None) -> ConstructionBundle
  if +RT:
      RuntimeSession.apply_bundle(bundle) → 执行闭环（≤2 revision）
      终态 bundle_vN
  盲评打包（bundle 中 MODEL_IR+code+输出，去 Constructor 身份标记）
```

**盲评**：3 独立 evaluator，κ ≥ 0.6 通过；盲包不暴露 arm/constructor 身份。

## 4. 预注册分析

- 混合效应：`MCQ ~ Constructor + Runtime + Constructor×Runtime + (1|problem)`
- 机械指标：逐项描述性 + 与盲评相关（Pearson/Spearman）
- 幂律：n=8 题/条件、每条件 2 seeds → 主效应可检
  （K001 教训：block 数 ≥ 6，K004 满足 8 block）

## 5. 判定规则（事先声明，避免事后叙事）

| 结果形态 | 解释 |
|---|---|
| `ΔRT > 0` 且机械指标同步 | Runtime 提升建模构造能力 |
| `ΔRT > 0` 但机械指标无变化 | 盲评偏好（格式/长度混淆）→ 不认 |
| `ΔRT ≈ 0` 且 Constructor 差异大 | Runtime 是"执行底座"而非"能力增强器"——定位仍成立（substrate 价值） |
| `ΔRT < 0` | Runtime 约束损害构造 → 停止该方向 |
