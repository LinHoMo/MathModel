## 1. 为什么需要锚定（归因，不是事后调阈值）

锚定前 5 份校准样本、3 名 evaluator 的两两维度级 κ：

| 指标 | 值 |
|---|---|
| 维度级 mean κ | 0.401（阈值 0.6） |
| 原始一致率 mean po | 0.709 |
| 期望一致率 mean pe | 0.608 |
| κ=0 但 po=0.80 的维度 | 6 个（L1.2/L1.4/L2.4/L3.1/L3.2 等）→ **Kappa 悖论伪影** |
| po < 0.7 的真实分歧维度 | 6 个：**L1.3 / L3.3 / L3.4 / L3.5 / L4.1 / L4.5** |

归因（两条，均已定位到机制层）：

**归因 A — 证据缺位导致的自由推断（主因）**
K002 是**纯表示实验**：108 份产物的构成是 S 臂 `model_ir.json`、SV 臂 `model_ir.json +
validation_plan.json`、F 臂 `model_doc.md`，**没有代码、没有 execution_result、没有数值结果**。
而 L3.2–L3.5 与 L4.1–L4.5 的 v1.1 判据大量引用"执行日志 / exit code / 残差序列 / 多 seed 运行
记录 / 对比结果"。证据不存在时，三名 evaluator 各自按不同隐式假设补位（一人从严判 0、
一人按声明判 2），在 L3.3 / L3.5 上出现 po = 0.00 的完全分歧。
→ 这是**判据未定义"证据缺位时如何评分"**，不是评分者能力问题。

**归因 B — 档位与满分不一致（次因）**
Rubric v1.1 正文对 **L3.5** 与 **L4.3** 描述了 0/1/2 三档，但盲评评分表与
`k002_analysis.py` 的满分常量把两者定为 **满分 1**（L3_MAX=9、L4_MAX=9 由此而来）。
档位-满分冲突使不同 evaluator 选用不同档位表，直接压低 κ。
→ 这是**文件内部不一致**，不是评分者分歧。

修复后预期：归因 A 由 §2 消除（证据缺位时改按"声明的可执行性设计"评分，判据显式化）；
归因 B 由 §3 消除（L3.5/L4.3 统一为二档 0/1，与满分一致）。

## 2. 锚定规则 A：证据缺位时的 L3 / L4 评分口径（核心）

**总原则**：K002 全 108 份产物均无执行证据。评分对象因此统一为
**"求解与验证的『设计』是否完备、自洽、可执行/可验证"**，而非"执行是否成功"。
`evidence` 字段中凡按本口径评分的维度，**必须写入 `no-exec-artifact` 标记**，
使后续分析可区分"声明层评分"与"执行层评分"。

### L3.1 求解策略匹配（0–2）
- 2 = 声明的求解方法与模型类型、参数口径完全匹配（如 MIP → 分支定界；PDE → 有限差分；排队 → 蒙特卡洛）
- 1 = 方法基本匹配但缺口径细节（无步长/精度/收敛容差）
- 0 = 方法与模型不匹配，或无求解方法声明

### L3.2 可执行性设计（0–2）〔无代码/无执行产物〕
- 2 = 有 `implementation_ref`（或等价的代码路径/算法步骤）+ 明确的输入-输出约定
      + 依赖/环境或数据可得性说明 → **可执行性有据可查**
- 1 = 有求解方法声明，但无实现路径或输出约定
- 0 = 无任何求解实现层面的声明
- **禁止**因"没有看到运行结果"直接判 0（产物本身不含执行证据，非产物缺陷）

### L3.3 收敛性（0–2）〔无数值结果〕
- 2 = 解析解 / 精确算法（收敛性由方法内在保证，**默认 2**），
      或声明了收敛判据与检验方式（如网格收敛、残差阈值、样本量收敛）
- 1 = 声明收敛但无判据、无检验方式
- 0 = 未讨论收敛性，或明确声明发散/不稳定

### L3.4 可复现性设计（0–2）〔无 replay 记录〕
- 2 = 显式多种子设计（**seeds ≥ 5 且 seed 固定**）+ 稳定性判据（如 cv < 10% / tolerance）
      （SV 臂由 `validation_plan.multi_seed` 机械支撑；S/F 臂看 `experiments[].reproducibility` 或等价声明）
- 1 = 提及多种子或固定 seed，但缺一项（种子数 < 5、未固定 seed、或无判据）
- 0 = 无任何可复现性设计

### L3.5 结果合理性 —— **二档 0/1**（见 §3）
- 1 = 给出了预期结果的量级/范围且与题面物理量级相符（`experiments[].expected_outputs` 或等价叙述）
- 0 = 无任何预期结果声明，或声明的量级明显不合理

### L4.1 对照基线（0–2）
- 2 = 有明确对照基线（零模型/随机基线/文献基准/贪婪启发式等）**且报告了对比判据或预期对比结论**
- 1 = 有基线但选择不当（过于简单或不相关），或未说明对比判据
- 0 = 无任何对照基线
- 注意：K002 产物中 `validations[].type` 的 `reproducibility` 是登记期的**脱盲改写值**，
  原语义可能包含"基线对比"。**按字段内容与上下文语义判定，不按字面枚举值判定。**

### L4.2 灵敏度分析（0–2）
- 2 = 有参数扰动分析，扰动了**敏感参数**，并报告弹性系数或鲁棒性边界
- 1 = 有灵敏度分析但扰动参数不敏感，或未报告弹性/边界
- 0 = 无灵敏度分析

### L4.3 极限/边界检验 —— **二档 0/1**（见 §3）
- 1 = 有 ≥1 类极限/边界/退化情形检验（极端参数、边界值、退化到已知解均可）
- 0 = 完全没有极限或边界检验
- （检验结果是否关联主张，写入 evidence，不作为 0/1 判据——因无执行结果可关联）

### L4.4 验证目标正确性（0–2）
- 2 = 验证设计覆盖模型的**全部核心主张**，且验证指标与题面 evaluation_targets 对应
- 1 = 覆盖部分核心主张，有遗漏
- 0 = 验证的是与主张无关的目标

### L4.5 证据-主张对应（0–2）
- 2 = 每条 claim 都有 `evidence_refs` 且引用可解析到产物中的 experiment/validation，
      状态为 supported/refuted（**无 unresolved**）
- 1 = 大部分 claim 有证据，但有 unresolved 或引用不可解析
- 0 = 存在无证据的 claim（unsupported）

## 4. 锚定规则 C：L1.3 交付要求识别（消除多附件粒度分歧）

预检期已知分歧点：多附件题目（如"填入附件 2 的 EXCEL 表"）的交付粒度。

- 2 = 识别了全部交付要求，包括**文件格式、精度、时间范围、特定附件/工作表**等具体规格
- 1 = 识别了主要交付物但规格有遗漏（如只说"输出结果"未提附件表格/精度）
- 0 = 未识别交付要求
- 判定依据：**题面原文**中出现的交付动词（"填入""给出""分别""精确到"）是否被产物覆盖，
  不要求逐字复述题面。

## 5. 锚定规则 D：格式中立（沿用 v1.1 §0.4，强化执行）

- 结构化产物（MODEL_IR JSON）：**字段齐全且内容正确 = 满分**，不因"未展开叙述"扣分
- 叙述式产物（model_doc Markdown）：**明确表达对应内容 = 满分**，不因"篇幅长"额外加分
- 每个维度先问"这个维度的信息在产物中**是否可查**"，再按判据打分；不可查才扣分
- **产物长度不作为评分依据**（F 臂产物可能显著短于 S/SV 臂，这是实验操纵的正常结果，
  不是质量信号）
