考虑如下的小游戏：玩家凭借一张地图，利用初始资金购买一定数量的水和食物（包括食品和其他日常用品），从起点出发，在沙漠中行走。途中会遇到不同的天气，也可在矿山、村庄补充资金或资源，目标是在规定时间内到达终点，并保留尽可能多的资金。

游戏的基本规则如下：
（1）以天为基本时间单位，游戏的开始时间为第0天，玩家位于起点。玩家必须在截止日期或之前到达终点，到达终点后该玩家的游戏结束。
（2）穿越沙漠需水和食物两种资源，它们的最小计量单位均为箱。每天玩家拥有的水和食物质量之和不能超过负重上限。若未到达终点而水或食物已耗尽，视为游戏失败。
（3）每天的天气为"晴朗"、"高温"、"沙暴"三种状况之一，沙漠中所有区域的天气相同。
（4）每天玩家可从地图中的某个区域到达与之相邻的另一个区域，也可在原地停留。沙暴日必须在原地停留。
（5）玩家在原地停留一天消耗的资源数量称为基础消耗量，行走一天消耗的资源数量为基础消耗量的2倍。
（6）玩家第0天可在起点处用初始资金以基准价格购买水和食物。玩家可在起点停留或回到起点，但不能多次在起点购买资源。玩家到达终点后可退回剩余的水和食物，每箱退回价格为基准价格的一半。
（7）玩家在矿山停留时，可通过挖矿获得资金，挖矿一天获得的资金量称为基础收益。如果挖矿，消耗的资源数量为基础消耗量的3倍；如果不挖矿，消耗的资源数量为基础消耗量。到达矿山当天不能挖矿。沙暴日也可挖矿。

3. 现有n名玩家，他们有相同的初始资金，且同时从起点出发。若某天其中的任意k(2<=k<=n)名玩家均从区域A行走到区域B(B不等于A)，则他们中的任一位消耗的资源数量均为基础消耗量的2k倍；若某天其中的任意k(2<=k<=n)名玩家在同一矿山挖矿，则他们中的任一位消耗的资源数量均为基础消耗量的3倍，且每名玩家一天可通过挖矿获得的资金是基础收益的1/k；若某天其中的任意k(2<=k<=n)名玩家在同一村庄购买资源，每箱价格均为基准价格的4倍。其他情况下消耗资源数量与资源价格与单人游戏相同。

  - 最优子结构：全局最优可由子问题最优组合而成
  - 重叠子问题：递归中反复访问相同子问题，表格化/记忆化消除重复
  - 无后效性（马尔可夫性）：当前状态已包含影响未来决策的全部相关信息，历史可丢弃

  - 确定性 DP 递推：V_t(s) = max_a { r_t(s,a) + V_{t+1}(s') }
  - 随机 MDP 贝尔曼方程：V*(s) = max_a { R(s,a) + γ·Σ_{s'} P(s'|s,a)·V*(s') }

  - 转移方程错误：动作对状态的影响未正确建模

### 2.2 建模结构案例

# 结构案例：穿越沙漠 —— 从题面到模型的结构骨架

> 本案例**只提供建模结构骨架**，不含解答、不含数值结果、不含具体策略。
> 它的作用是示范「如何把这类题面拆成状态 / 决策 / 约束 / 目标」，而不是告诉你该怎么解。

## 1. 结构识别路径

按下面五问逐条核对题面，全部命中即为**多阶段序贯决策**结构：

1. 时间是否天然可数？—— 以「天」为基本单位，阶段可数。
2. 每阶段是否必须做一次选择？—— 每天要选择行动方式与目标节点。
3. 当天的选择是否改变下一天的状态？—— 位置、资源、资金都被改变。
4. 目标是否跨阶段累积？—— 终点保留资金是全程累积量。
5. 历史信息能否压缩进当前状态？—— 只要记录位置与存量，之前走了哪条路就不再影响未来。

**关键判断**：第 5 问是最容易出错的一步。压缩失败意味着递推不成立，
此时无论用什么算法都是错的。

## 2. 状态变量的构造

状态需要覆盖以下分量（缺一即破坏可压缩性）：

| 分量 | 含义 | 类型 |
|---|---|---|
| 位置 | 当前所在地图节点 | 离散 |
| 剩余水 | 资源存量 | 离散（需离散化） |
| 剩余食物 | 资源存量 | 离散（需离散化） |
| 剩余资金 | 累积收益 | 离散 |
| 已用天数 | 阶段计数 | 离散 |
| 天气 | 随机环境状态 | 离散（有限状态集） |

构造顺序建议：先写出「影响明天能做什么」的全部量，再逐个问
「去掉它，未来的最优决策会不会变」，不会变的才剔除。

## 3. 决策变量与约束骨架

- **决策**：当日的行动方式 + 目标节点（含原地停留这一选项）
- **约束族**：
  - 负重上限（资源总量约束，方向为 ≤）
  - 资源存量非负（每阶段都必须成立）
  - 到达终点的期限（方向为 ≤，是截止时间而非目标）
  - 地形通行限制（只允许相邻节点转移）
  - 天气对消耗量的放大（乘性因子，作用在消耗项而非状态项）

**核对方向**：资源类约束是上界，生存类约束是下界，
两类写反会让模型在数学上「可解但物理上荒谬」。

## 4. 目标骨架

最大化终点时刻的资金存量。若题面涉及随机性或风险，
目标需改写为期望形式，或保留原目标但增加「不因资源耗尽而失败」的生存约束。

写法上要区分：
- **目标函数**（要优化的单一标量）
- **约束**（必须满足的条件，不参与优化权衡）

把「必须活着到达」写进目标函数而不是约束，是这类题最常见的建模错误。

## 5. 候选机理与选择依据

| 候选机理 | 成立条件 | 本题适用性判断 |
|---|---|---|
| 确定性多阶段递推 | 天气已知或按期望处理 | 可作为基础模型 |
| 随机动态规划 | 天气服从已知分布，需取期望 | 引入天气后必须转为此形式 |
| 蒙特卡洛仿真 | 转移复杂或状态维数过高 | 适合做验证，不适合做求解主路径 |
| 博弈分析 | 存在多个决策主体互相影响 | 仅在多方策略对比时才需要 |

选择依据只有两条：**最优子结构是否成立**、**无后效性是否成立**。
两者都依赖第 2 节的状态定义是否完整，而不是依赖算法偏好。

## 6. 常见坑

- 状态里漏掉天气 → 同一状态在不同天气下最优决策不同，递推失效。
- 用「每天走当前最优」的贪心替代全局递推 → 局部最优不等于全局最优。
- 把连续资源量直接放进状态 → 状态集不可数，必须先离散化并检验粒度敏感性。
- 只报一条最优路线，不报期望与波动 → 无法判断策略鲁棒性。
- 混入与地图无关的主观假设（如凭直觉设定停留收益）而不标注来源。

## 7. 验证骨架

1. **小规模对照**：把天数压到极小，暴力枚举全部策略，与递推结论比对。
2. **回溯一致性**：从递推结果反推策略，手动模拟一遍，累积量必须与递推值相等。
3. **参数扰动**：改变天气分布与消耗参数，观察最优策略是否稳定。
4. **松弛下界**：去掉部分约束求松弛解，其目标值应不劣于原模型。
