# 交巡警服务平台设置与调度模型

## 1. 问题理解

**核心矛盾**：警务资源有限，需在"出警时效（3 分钟到达）"、"工作量均衡"、"快速封控/围堵"三个目标间权衡；平台设置是长期决策，警力调度是短时决策。

**关键实体**：交通网络（节点=路口、边=道路）、平台（20 个于 A 区 + 六区分布）、出入城路口（13 条要道）、警车（60 km/h）、嫌疑犯（P 点案发后逃逸）。

**子问题分解**：
- Q1a：20 平台管辖范围分配（3 分钟 = 3km 覆盖半径）；
- Q1b：13 条要道全封锁调度（一平台最多封一路口）；
- Q1c：增加 2–5 个平台的位置与个数；
- Q2a：全市六区现有设置合理性分析；
- Q2b：P（第 32 节点）案发 3 分钟后报警的围堵方案。

**显式条件**：警车时速 60km/h → 3 分钟行驶 3km；A 区 20 平台、13 条要道；新增平台 2–5 个；P 为第 32 个节点；案发 3 分钟后报警。

**隐式条件**：平台警力封锁一个路口后不能再封锁其他（Q1b）；嫌疑犯车速未知需假设（本模型取与警车相同或略高，作为鲁棒性参数）；围堵需在嫌疑犯到达出城路口前完成布防。

**歧义点**：
1. "尽量能在 3 分钟内到达"：采纳为硬性约束（90% 节点覆盖 + 优化覆盖缺口），而非软目标；
2. 嫌疑犯车速：采纳取警车速度 60km/h 的 1.2 倍（72km/h）做鲁棒设计，并做速度灵敏度分析；
3. "工作量不均衡"的度量：采纳平台管辖节点数（或出警需求加权）的方差。

**问题类型判定**：核心范式为"图论/网络优化（覆盖、指派、最短路）+ 组合调度（封锁、围堵）"。

## 5. 目标

- Q1a：**最小化**未覆盖节点数（主）与平均到达时间（次）：$\min \sum_i (1-c_i)$，tie-break $\min \bar t_{ij}$；
- Q1b：**最小化**封锁完成时间：$\min T_{max} = \max_k t_{j(k),k}$（指派 13 平台到 13 要道）；
- Q1c：**最小化**平台工作量方差 + 覆盖缺口：$\min \mathrm{Var}(W_j) + \lambda \sum_i (1-c_i)$；
- Q2a：**估计**六区平台配置的合理性指标（覆盖率、工作量均衡、服务半径）；
- Q2b：**最小化**围堵完成时间并保证嫌疑犯无法逃脱：$\min T_{encircle}$ s.t. 所有出城通道在嫌疑犯到达前被封锁。

## 6. 约束

| 表达式 | 方向 | 来源 | 子问题 |
|---|---|---|---|
| $\sum_j x_{ij} = 1$（每节点恰好一个管辖平台） | = | 模型假设 | Q1a |
| $t_{ij} \le 3$ 尽量满足（硬约束于关键节点） | ≤ | 题面 | Q1a,Q2a |
| $\sum_k y_{jk} \le 1$（一平台至多封一路口） | ≤ | 题面 | Q1b,Q2b |
| $\sum_j y_{jk} = 1$（每要道必须被封） | = | 题面 | Q1b |
| $2 \le n_{add} \le 5$ | ≤ | 题面 | Q1c |
| 围堵：$t_{arr}^{suspect}(B_m) \ge t_{arr}^{police}(B_m)$ 对所有出城节点 | ≥ | 物理限制 | Q2b |

## 7. 机理

问题本质是**图上的覆盖与指派**：管辖分配是"设施覆盖问题"（每个节点指派给最近平台并满足时间约束）；封锁是"指派问题/瓶颈指派"（最小化最大完成时间）；围堵是"动态最短路 + 抢占布防"问题。核心数学结构是图论最短路 + 组合优化。

**候选模型对比**：
1. **最短路 + 覆盖模型（Dijkstra + 指派）**——优：简洁、可解释、直接回答 Q1a/Q1b；劣：不考虑道路动态。**选为最终框架**。
2. **整数规划（ILP 精确求解）**——优：最优性保证；劣：规模大时求解慢，但对本题规模（≤92 节点）可行，作为求解器。
3. **启发式（贪心覆盖 + 局部搜索）**——优：快；劣：最优性无保证。作为对照与大规模备用。
4. **仿真（交通流微观模拟）**——劣：数据需求大，本题静态图足够。排除。

## 8. 方程

**最短路**（Dijkstra）：$d_{ij} = \min_{\text{path } P(i\to j)} \sum_{e\in P} w_e$，其中 $w_e = l_e / v_p$（分钟）。

**覆盖约束**：$c_i = \mathbb{1}[\min_j d_{ij} \le 3]$。

**瓶颈指派**（Q1b）：
$$\min_{y} \max_{k} \sum_j y_{jk} d_{j,k}, \quad \text{s.t. } \sum_j y_{jk}=1,\ \sum_k y_{jk}\le 1$$

**围堵可行性**（Q2b）：对出城节点集合 $\mathcal{E}$，要求
$$d(P, B_m)/v_s + 3 \ge d_{j^*(B_m), B_m}/v_p, \quad \forall B_m\in\mathcal{E}$$
其中 $j^*(B_m)$ 为派往 $B_m$ 的平台。

## 9. 求解与验证

**求解策略**：Dijkstra 全对最短路径；Q1a 用最近平台指派 + 覆盖缺口统计；Q1b 用匈牙利算法/瓶颈指派；Q1c 用 ILP 枚举 2–5 个新增平台；Q2b 用"嫌疑犯最坏可达集"动态扩张判断围堵节点集合。复杂度：Dijkstra O(N log N + E)，指派 O(K³)。

**可复现性**：确定性图算法无需随机种子，但对嫌疑犯车速等不确定参数做多场景（λ=1.0/1.2/1.5）检验。

**验证方案**：
1. 基线对照：单一平台覆盖半径理论值 vs 模型覆盖统计；
2. 灵敏度：$v_s$ 与报警延迟 $\Delta t$ 变化对围堵方案影响；
3. 极限：$v_p\to\infty$ 时覆盖全图；$n_{add}=0$ 时退化为原方案；
4. 结构一致性：Q1b 封锁时间 ≤ 最远平台到要道的最大最短路；
5. 交叉检验：六区合理性指标与 A 区指标口径一致。

**结果合理性预期**：A 区 20 平台 3km 半径下覆盖率应达 80% 以上；13 条要道封锁完成时间约 5–10 分钟；新增 2–5 平台后覆盖缺口显著下降。若偏离，按"路网数据→速度假设→指派规则"归因。
