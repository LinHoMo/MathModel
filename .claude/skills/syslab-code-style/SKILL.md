# Syslab 代码风格

先使用 `syslab-environment`。相对路径：`../syslab-environment/SKILL.md`。
默认代码运行在 Syslab 内部；当存在等价功能时，优先使用 `Ty*` 库。

本技能以 `references/BlueStyle.md` 为基础。
不要在回复中复制整份指南。
应用那些能切实提升可读性、一致性和可维护性的部分。

## 保持代码格式一致

- 每一级缩进使用 4 个空格，绝不使用制表符。
- 除非周围文件已经采用了不同约定，否则将单行长度控制在接近 92 个字符以内。
- 在长形式函数和逻辑代码块之间保留一个空行。
- 避免行尾空白和无意义的额外垂直留白。

## 使用可预期的命名

- 模块和类型使用 `UpperCamelCase`。
- 函数和方法使用 `lower_snake_case`。
- 如果代码库已经采用该模式，就为明显仅供内部使用的辅助函数添加 `_` 前缀。
- 相比 MATLAB 风格的编码式命名，更优先使用简短、面向动作的函数名。

## 组织好导入与导出

- 将 `using` 语句放在文件顶部附近，或紧接在 `module` 之后。
- 优先每行只导入一个包。
- 保持导入顺序稳定且便于扫读。
- 在顶层模块定义附近导出公共 API。
- 当显式导入能提升包代码的可读性时，优先使用显式导入。

## 以清晰为目标编写函数

- 一旦函数定义无法再清晰地写成单行，就优先使用长形式的 `function ... end`。
- 在长形式函数中使用显式 `return`。
- 通过参数传递数据，而不是读取可变的全局变量。
- 类型标注在满足分派和复用需要的前提下尽量保持通用。
- 调用函数时，用 `;` 分隔位置参数和关键字参数。

## 让注释和文档字符串保持高信息密度

- 注释应说明意图、不变量和不明显的约束。
- 不要为显而易见的语法写注释。
- 为导出的函数、公共类型和公共模块添加文档字符串。
- Markdown 文档字符串要保持简洁，并在有帮助时围绕参数、关键字、返回值和异常来组织结构。

## 绘图约定

使用 TyPlot 创建图形时，默认处于 hold("off") 状态。也就是说，后续绘图通常会替换当前图中的已有内容。若要在同一图中叠加多个元素，例如数据点、拟合曲线或多组序列，应在添加后续内容前显式调用 hold("on")。

## 保持低噪声差异

- 不要大规模格式化无关文件。
- 当本地项目约定是有意偏离 BlueStyle 时，以项目自身约定为准。
- 仅在你已经修改相关代码时，顺手修复周边的风格问题。

## 审查检查清单

在审查或重写代码时，优先检查以下内容：

- 应改为函数参数或 `const` 的全局变量
- 不一致的命名
- 长形式函数中缺失的 `return`
- 杂乱或无序的导入
- 导出 API 缺失文档字符串
- 过于具体、降低复用性的类型标注
