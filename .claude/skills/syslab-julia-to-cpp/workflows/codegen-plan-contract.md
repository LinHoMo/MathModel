# 代码生成计划合同

所有 Julia 到 C++ 代码生成任务，在开始编译前都要先形成完整计划。

## 强制字段

计划中必须包含：

- 目标产物模式
- 入口文件与入口函数
- 若使用 `build.jl`，用户明确指定的 `main()` 目标函数或 `static_compile(...)` 导出清单
- 若目标为 `source`，其底层对应的 `app` / `shared` 语义，以及 `-c` / `--no-compile`、`-d <dir>` 的用法
- 目标平台
- 编译命令草案
- 兼容性检查结果
- 验证方案

## 禁止事项

- 不能在未识别 `app` / `shared` / `source` 模式前直接试编译。
- 不能在未检查导出签名时直接承诺动态库可用。
- 不能把“编译成功”当作“对外接口可用”。
- 不能在未记录用例文件时使用 `--collect-instance`。
- 未经用户明确授权，不能直接修改用户 Julia 源文件；若仅缺少 `main()`、`SyslabCC.static_compile(...)`，必须优先采用同目录 `build.jl` 方案；只有 `build.jl` 方案不足时，才写 `docs/{entry-name}/source_change_suggestions.md`。
- 当 `app` / `shared` 需要通过 `build.jl` 补充入口或导出时，不能在用户未明确指定目标函数前自行编造 `main()` 调用链或 `static_compile(...)` 签名。

## 完成标准

只有当以下条件满足时，计划阶段才算完成：

- 入口模式已经明确
- 关键风险已经记录
- 第一条编译命令已经写明
- 验证方式已经确定
- 若使用 `build.jl`，用户指定的入口或导出项已经记录
