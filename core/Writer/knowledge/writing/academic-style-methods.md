# 学术写作方法论与文风自然化（academic-style-methods.md）

> 来源：对标 econ-writing-skill 名家方法论 + PaperForge 反 AI 检测文风。
> 定位：本文是「改写方法论」——教你把初稿从「可读」提升到「有论文感、无 AI 味」。
> 分工（避免与既有文档重复）：
> - `transition-phrases.md` → 过渡词与句式变化的**词汇表**；
> - `forbidden-words.md` / `avoid-ai-writing-en.md` → 禁用词的**黑名单**；
> - 本文 → 把禁用词所在句子**重写**成有信息量的学术表达的**手法与原则**。

## 一、名家写作方法论 5 原则（先学骨架，再谈词句）

### 1. 先结论、后论证（演绎结构）

每段第一句给出本段结论，后面才是推导与证据。读者扫一眼首句就该知道这段要说什么。

反例（结论埋在结尾）：

```
本文考虑了XX、YY、ZZ三个因素，通过对比分析，最终发现……
```

正例（结论前置）：

```
本模型的最优方案为方案二。论证如下：……（影响因素、对比过程）……
```

### 2. 具体 > 抽象（用数据/事实替代空泛形容词）

空泛形容词（如「显著」「较好」「有效」「合理」）是 AI 生成文本的重灾区——没有信息量，还显得在凑字数。能落成数字的，一律落成数字；数字来自 `figures/all_results.json`，不得重估。

反例：

```
该方法显著提高了求解效率，取得了较好的效果，证明了模型的合理性。
```

正例：

```
该方法将单次求解时间从 12.3 s 降至 0.8 s（提速约 15 倍），且目标函数值下降 3.2%，模型相对误差控制在 1.5% 以内。
```

### 3. 长短句交替，避免「复读机」节奏

连续多个同构长句会暴露模板感。长短句穿插，关键结论用短句收束。

反例（三连排比长句）：

```
本文首先建立了XX模型，接着采用YY算法进行求解，最后对结果进行了ZZ分析。
```

正例（长短交替）：

```
本文建立 XX 模型。为求解该模型，采用 YY 算法。结果见表 2。
```

### 4. 主动语态优先，动词优先（中文数模论文的「工程文风」）

过度被动与名词化是 AI 味的另一源头。把「进行了分析」改成「分析了」，把「对……进行建模」改成「建立……模型」。

| 名词化（AI 味） | 动词化（自然） |
|---|---|
| 对数据进行了预处理 | 预处理数据 |
| 对模型进行了求解 | 求解模型 |
| 产生了显著的影响 | 显著影响（或直接写数字） |
| 进行了一系列的优化 | 逐步优化 |

### 5. 一段一中心，中心句落在段首

每段只讲一件事，段首句是全段论点。段落间用 `transition-phrases.md` 的过渡词连接，但过渡词要「服务论证」，不是「凑衔接」。

## 二、反 AI 痕迹：从「拦截」到「改写」

`guardrails-checker`（L5）的职责是**拦截**——命中禁用词/占位符/分点式就退回。但「没有禁用词」不等于「没有 AI 味」。本文把 L5 从「拦截」升级为「改写优化」：识别 AI 套话的**句式结构**，整句重写。

### 2.1 AI 套话的典型句式（重写对象）

| 套话句式 | 问题 | 改写方向 |
|---|---|---|
| 「随着……的快速发展，……越来越重要」 | 万能开头，无信息量 | 直接进入问题本身 |
| 「值得注意的是 / 值得一提的是」 | 元叙述，删掉不影响 | 删除，直接写内容 |
| 「综上所述，本文……，具有一定的参考价值」 | 空泛收尾 | 用具体结论 + 局限收尾 |
| 「不可忽视 / 不可否认」 | 故作姿态 | 删，或写具体数值 |
| 「深入探究 / 全面分析 / 系统研究」 | 空泛大词 | 写具体做了什么 |

### 2.2 改写三手法

1. **删元叙述**：删掉「本文认为 / 值得注意的是 / 需要指出」这类只起「占位」作用、不传递信息的话头。删掉后句子若不通，说明后面本来就没内容——补内容，而不是补话头。
2. **数字落地**：每个抽象结论追问「具体是多少？来自哪个表？」，数字一律引 `figures/all_results.json`（铁律 W1），不给数字的形容词直接删。
3. **句式翻新**：被动改主动、名词化改动词、排比改长短句（见 §一 第 3/4 条）。

### 2.3 综合改写示例

初稿（典型 AI 味）：

```
随着人工智能技术的快速发展，数据处理在数学建模中扮演着越来越重要的角色。
值得注意的是，本文针对XX问题，提出了一种基于YY的建模方法，
对模型的性能进行了全面的分析。综上所述，该方法具有一定的应用价值。
```

改写后：

```
本文针对 XX 问题建立基于 YY 的模型。该方法将求解误差从 8.4% 降至 1.2%，
并在 100 组随机实例上平均提速 20 倍（表 3）。模型在数据稀疏时仍保持稳定，
但假设变量线性相关，向非线性场景推广前需进一步放宽该假设。
```

改写要点：删「随着……快速发展」「值得注意的是」「综上所述」；「全面分析」→ 落成两个数字；「一定应用价值」→ 具体局限与改进方向。

## 三、检查清单（成文后逐项过）

- [ ] 每段首句是该段结论，读者只看首句即知本段主旨
- [ ] 无「随着……的快速发展」「值得注意的是」「综上所述」等元叙述套话
- [ ] 每个抽象形容词（显著/较好/有效/合理/一定）要么落成具体数字、要么已删除
- [ ] 无三连以上同构长句，关键结论用短句收束
- [ ] 主动语态为主，「进行了/对……进行」式名词化已改动词化
- [ ] 数字全部来自 `figures/all_results.json`，无重估（铁律 W1）
- [ ] 段落间过渡自然（引用 `transition-phrases.md`），非生硬堆砌
