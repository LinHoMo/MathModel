# Writer Laws

## 六层防御体系

本角色嵌入六层防御体系，每条铁律对应防御层次：

| 铁律 | 防御层次 | 执行机制 |
|------|---------|---------|
| W1 | L1+L6 结构化输出+事后验证 | traceability.numbers_traced必须为true |
| W2 | L1 结构化输出 | abstract.sub_problem_summaries必须含数值 |
| W3 | L1 结构化输出 | assumptions必须有necessity字段 |
| W4 | L3 过程验证 | ProcessVerifier检查figures_have_analysis |
| W5 | L5 运行时护栏 | Guardrails检查引用完整性 |
| W6 | L5 运行时护栏 | Guardrails检查禁用词 |
| W7 | L5 运行时护栏 | Guardrails检查内部路径 |
| W8 | L5 运行时护栏 | Guardrails检查占位符 |
| W9 | L3+L6 过程验证+事后验证 | ProcessVerifier+validate.py检查 |
| W10 | L1 结构化输出 | quality_checks.model_evaluation_exists |
| W11 | L5 运行时护栏 | Guardrails 检查列表环境 |
| W12 | L5 运行时护栏 | Guardrails 检查图表引用句式 |
| W13 | L1 结构化输出 | Schema 检查 abstract 字段 |
| W14 | L1 结构化输出 | Schema 检查 target_pages 字段 |

## 铁律（不可违反）

### W1: 论文中每个事实/数值必须经 Evidence Graph 解析到已验证的 Result Artifact
- **防御层次**: L1 + L6 结构化输出 + 事后验证
- **V3 语义（权威）**: 每个数值/事实性陈述必须沿 Evidence Graph 的 `supports` / `produces`
  关系解析到一个 `validated` 状态的 Result Artifact（`core/runtime/graph/evidence_graph.py`）。
  论文数值来源 = Result Artifact，而不是写作时重新估算。
- **V2 物理载体（兼容）**: legacy 流水线中 `figures/all_results.json` 仍是 Result 的物理
  载体与 L5/L6 校验对象；V3 下它被 Registry 登记为 result Artifact 的 provenance。
- **典型反例**:
  - 摘要写 95.2% 正文写 95.3%，口径不一致，评委质疑数据真实性
  - 图表数值与账本差 0.01（四舍五入口径不同），追溯失败
  - 论文阶段重新估算或换四舍五入口径，与账本脱节
- 论文中每个数字必须能经 Evidence Graph 追溯到 Result Artifact（legacy：`figures/all_results.json`）
- 摘要和正文数值必须一致
- 图表中的数值必须与代码输出一致
- 禁止在论文阶段重新估算或换一套四舍五入口径

### W2: 摘要必须包含每个子问题的具体数值结果
- **防御层次**: L1 结构化输出
- **典型反例**:
  - 摘要只写"效果良好""结果最优"无数值，评委无法快速判断成果
  - 漏掉某个子问题的结果（只覆盖问题一、二，漏问题三）
  - 摘要先写，正文修改后摘要数值未同步更新，与正文矛盾
- 每个子问题必须覆盖：方法 + 模型 + 关键结果（含数值）
- 不要出现复杂公式和表格
- 不要只重述题目
- 不要用"我们认为……"等空泛表述
- 应最后撰写（内容全部确定后）

### W3: 每个假设必须有必要性说明
- **防御层次**: L1 结构化输出
- **典型反例**:
  - 假设只列"假设匀速运动"不说明为什么需要这个假设，必要性缺失
  - 假设在正文建模处从未被引用，形同虚设
  - 假设列了 10 条但建模只用 3 条，多余假设无必要性说明
- 不是简单列出假设
- 必须说明为什么需要这个假设
- 假设对模型的影响

### W4: 每张图表前后必须有分析文字
- **防御层次**: L3 过程验证
- **典型反例**:
  - 连续 3 张图中间无文字，论文变成图集
  - 图表前无引导文字，读者不知图要说明什么
  - 图表后只有"如图所示"无分析，图表失去论据作用
- 每张图/表前需要 1-2 句引导文字
- 每张图/表后需要 3-5 句分析
- 连续两张图/表之间必须有至少一个完整段落
- 图表是论据不是主语

### W5: 参考文献必须真实存在，不可捏造
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - `\cite{key}` 但 references.bib 无此 key，编译报 undefined citation
  - 引用作者/年份/期刊与真实记录对不上（张冠李戴）
  - 网络检索失败后补造引用，文献实际不存在
- 只引用实际检索并核对过的来源
- BibTeX 的题名、作者、年份、期刊和 DOI 必须对应真实记录
- 连续引用合并：`\citep{key1,key2,key3}`

### W6: 禁止使用AI痕迹词汇
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - 连续段落"首先……其次……最后……"机械模板，AI 味明显
  - "综上所述""值得注意的是""至关重要"等套话堆砌
  - "赋能、抓手、闭环、底层逻辑、颗粒度"等互联网黑话
- 参考 `core/Writer/knowledge/writing/forbidden-words.md`
- 禁止"值得注意的是"、"综上所述"等AI常用表达
- 使用自然、专业的学术语言

### W7: 禁止出现内部文件名、脚本名、临时目录
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - 正文出现"compute.py""main.py"等代码文件名，暴露工程细节
  - 出现"由 AI 生成""作为 AI"等过程痕迹
  - 出现临时目录路径如"C:\Users\xxx\"或"/tmp/work/"
- 正文中禁止出现代码文件名
- 禁止出现临时目录路径
- 禁止出现"由 AI 生成"等过程痕迹

### W8: 禁止有占位符残留
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - TODO/FIXME/TBD 残留在正文，未清理
  - `[待补充]`、`[此处插入图表]` 等占位符文本未替换
  - 模板示例数据未替换（如"示例数值 123""张三"等）
- 无 TODO/FIXME/TBD 残留
- 无占位符文本
- 所有内容必须是最终版本

### W9: 灵敏度分析必须存在
- **防御层次**: L3 + L6 过程验证 + 事后验证
- **典型反例**:
  - 完全无灵敏度分析章节，模型鲁棒性无法判断
  - 只扰动一个参数不扰动其他关键参数，分析不全面
  - 扰动后只报告新数值不报告变化幅度/趋势，分析无意义
- 对关键参数进行±10%、±20%扰动
- 分析结果对参数变化的敏感程度
- 展示模型鲁棒性

### W10: 模型评价必须诚实讨论缺点
- **防御层次**: L1 结构化输出
- **典型反例**:
  - 只写优点不写缺点，评价失衡，评委质疑客观性
  - "完美适用所有场景"过度宣称，与实际不符
  - 缺点泛泛而谈（"模型有局限性"）不具体说明局限在哪
- 诚实列出优点
- 诚实列出缺点和局限性
- 提出可能的改进思路
- 讨论模型的适用范围

## 写作防错速查表

> 从历年真题踩坑逆向整理，沉淀至本章写作防错速查表，覆盖摘要、正文与图表栏目。撰写阶段逐条核对，命中即修正。

### 摘要防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 先写后不改 | 摘要先写，正文定稿后数值未同步更新 | 摘要最后写，数值从正文复制 |
| 子问题遗漏 | 只覆盖部分子问题结果（漏问题三） | 每个子问题必须覆盖：方法+模型+关键数值 |
| 空话无数值 | "效果良好""结果最优"无具体数值 | 必须含具体数值（精度/最优值/排序结果） |

### 结构防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 章节顺序错 | 灵敏度放在模型建立前，逻辑混乱 | 按 摘要→重述→假设→符号→建模→求解→检验→灵敏度→评价→参考 |
| 假设未引用 | 假设列了但正文建模处从未引用，形同虚设 | 每条假设在建模处显式引用"由假设 H1 可知" |
| 符号未定义 | 公式符号首次出现处无定义，读者无法理解 | 符号说明表统一定义；首次出现处标注"见符号表" |
| 图表成图集 | 连续 3 张图中间无文字，论文变图集 | 每张图前 1-2 句引导，图后 3-5 句分析 |

### 数值防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 口径不一致 | 摘要 0.832 正文 0.8317，四舍五入不同 | 统一四舍五入口径（如统一 4 位小数），从账本复制 |
| 不可追溯 | 数值经 Evidence Graph 解析不到 validated Result Artifact（legacy：all_results.json 无对应记录） | 每个数值标注 Artifact ID / 账本 key，写入追溯表 |
| 论文阶段重估 | 论文阶段重新计算或估算数值 | 禁止重估；数值必须来自 Result Artifact（legacy：代码产出 all_results.json） |

### 引用防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| key 不存在 | `\cite{xxx}` 但 bib 无此 key，编译报 undefined | 编译前用脚本检查所有 cite key 在 bib 中存在 |
| 引用捏造 | 作者/年份/期刊对不上真实记录 | 只引用实际检索核对的来源；检索失败不补造 |
| 连续引用未合并 | [1][2][3] 分开排列，占用篇幅 | 合并为 `\citep{key1,key2,key3}` |

### 护栏防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| AI 痕迹词 | "首先/其次/最后"机械模板，"综上所述"套话 | 参考 forbidden-words.md，改用自然学术表达 |
| 内部路径 | 正文出现"compute.py""C:\Users\xxx" | 正文中清除所有代码文件名与临时目录路径 |
| 占位符残留 | TODO/FIXME/[待补充] 残留 | 用 `py validate_project.py --project projects/<项目>` 或 grep 扫描清除 |

## 铁律新增（对标 mmagent-codex-main）

### W11: 正文禁列表（正文/摘要禁止 itemize/enumerate）
- **防御层次**: L5 运行时护栏
- **执行机制**: Guardrails 检查列表环境
- **规则**:
  1. 论文正文（含摘要）中禁止使用 `\begin{itemize}` 和 `\begin{enumerate}` 列表环境
  2. 需要列举时改用自然段落叙述（"第一，...；第二，...；第三，..."）
  3. 列表环境仅允许在"符号说明表"和"附录"中出现
  4. 任何正文中出现 itemize/enumerate 即 FAIL（HARD 门禁）
- **违反后果**: 正文出现列表环境，L5 护栏 FAIL，必须重写该段落

### W12: 图表引用句式（禁止图表做主语句式）
- **防御层次**: L5 运行时护栏
- **执行机制**: Guardrails 检查图表引用句式
- **规则**:
  1. 禁止图表做主语句式："图X展示了""如图X所示""由图X可知""从图X可以看出"
  2. 正确写法：以数据/结论为主语，图表引用放在括号中
  3. 全文图表主语句式出现 ≥3 次即 FAIL（HARD 门禁，从 env/review.figure_as_subject_max 读取）
  4. 正确示例："实验结果表明，...（见图X）"而非"图X展示了实验结果表明..."
- **违反后果**: 图表主语句式 ≥3 次，L5 护栏 FAIL，必须重写相关段落

### W13: 摘要规格（摘要 400-600 字，每子问题含数值）
- **防御层次**: L1 结构化输出
- **执行机制**: Schema 检查 abstract 字段
- **规则**:
  1. 中文摘要字数必须在 400-600 字之间（从 env/paper.abstract_min_words / abstract_max_words 读取）
  2. 摘要中每个子问题必须包含具体数值结果（不得仅描述方法）
  3. 摘要不得出现"本文""我们"等元叙述词
  4. 摘要不得使用 itemize/enumerate 列表
- **违反后果**: 摘要字数不达标或缺少数值，L1 Schema FAIL，必须重写摘要

### W14: 版面规格（正文硬上限 20 页，软目标 17 页，填充率 ≥85%）
- **防御层次**: L1 结构化输出
- **执行机制**: Schema 检查 target_pages 字段
- **规则**:
  1. 论文正文页数（不含附录）尽量控制在 20 页以内（官方硬上限），软目标 17 页（从 env/paper.min_pages / max_pages 读取）
  2. 正文填充率 ≥85%（正文页数 ≥ max_pages × page_fill_ratio，国赛 0.85）
  3. 附录页数不计入正文页数，且附录页数不限（官方明文）
  4. 排版后 estimate_pages = total_chars / chars_per_page，若 < max_pages × page_fill_ratio 则 FAIL
- **违反后果**: 页数不达标或填充率不足，L1 Schema FAIL，必须扩充内容或调整排版
