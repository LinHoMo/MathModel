# Syslab MDS 帮助文档

## 定位

使用 `mdsSearch` 为 Syslab 知识类问题提供官方文档依据。把本技能用于文档检索和证据组织，不把它当作代码执行、环境检测或测试工具。

按仓库总入口先使用 `syslab-environment` 解析共享环境。如果问题还要求编写或运行代码，再调用相应的实现类技能。

## 强制规则

1. 先发现当前会话中真实可用的工具，不猜测 MCP 前缀。工具名可能显示为 `mdsSearch`，也可能带 `syslab-search` 命名空间。
2. 仅对概念、教程、原理、工作流、排障和最佳实践使用 MDS。具体函数名的语法、参数、返回值和调用示例优先走函数文档工具。
3. 严格遵循实时工具 schema。当前 `mdsSearch` 只有一个必填字符串参数 `query`；不要传 `top_k`、栏目或路径等不存在的参数。
4. 将用户问题改写成约 100 字的连贯“假设性答案”作为 `query`。不要传关键词列表，也不要原样复制用户问题。
5. 根据命中结果作答并标明标题或位置。不要把记忆中的内容伪装成检索结果，不要输出原始 JSON。
6. MDS 缺失或失败不阻断后续任务。说明降级来源，然后继续完成可安全完成的工作。

## 工作流

1. **判别问题类型**
   - 知识、教程、原理、工作流、排障、最佳实践：继续 MDS 流程。
   - 函数/API 的语法、参数、返回值：直接进入函数文档降级链。
   - 代码编写、运行、迁移或测试：先检索所需依据，再交给对应 `syslab-*` 技能执行。
2. **发现工具**
   - 检查会话工具列表和 schema，寻找真实的 `mdsSearch`。
   - 未发现时不要反复探测，直接进入降级链。
3. **路由主题**
   - 按 `references/doc-taxonomy.md` 选择一个主要文档域。
   - 只有首次结果为空或明显偏题时才换第二个域。
4. **构造查询**
   - 阅读 `references/tool-protocol.md`。
   - 写一段可能出现在答案中的自然语言说明，包含 Syslab 产品语境、目标、关键概念和预期做法。
5. **检索与重写**
   - 调用一次 `mdsSearch`。
   - 若结果为空或无关，换角度重写一次 `query`；不得使用完全相同的参数重试。
   - 鉴权、网络或服务错误时停止 MDS 重试并降级。
6. **组织答案**
   - 按 `references/answer-contract.md` 输出直接答案、文档依据和必要的可用性说明。
   - 若结果相互冲突、版本不明或证据薄弱，明确标注不确定性。

## 降级链

按问题类型和当前会话实际可用工具选择：

1. `mdocsSearch`：已明确函数名，需查语法、参数、返回值或调用示例。
2. `search_syslab_docs` + `read_syslab_doc`：检索和读取已部署的本地 Syslab 帮助语料。
3. `syslab-environment` 定位的 `<SYSLAB_HOME>/Tools/AIAssets/projects`：直接检索本机帮助文件。
4. 现有 `syslab-*` 技能的 `references/`：仅用于其覆盖的专门领域。
5. 基于通用知识谨慎回答：明确说明本轮没有取得 Syslab 官方帮助原文。

工具名称可能被宿主加前缀；始终以实时工具列表和 schema 为准。
