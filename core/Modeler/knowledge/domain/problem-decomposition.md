# 题型 × 子任务分解原则（problem-decomposition.md）

> 来源：LLM-MM-Agent `MMAgent/prompt/decompose_prompt.json`（NeurIPS 2025，竞争分析 C-1）。
> 目的：把「一道赛题应拆成哪些子任务、子任务间如何衔接」显式化，供 `problem-parser` / `model-builder` 参考，避免「上来就建模、结构混乱」。
> 使用方法：先由 `type-classifier` 判定题型（A~F），再对照下表确定子任务数与每个子任务的职责，串成可执行步骤。

---

## 总则

1. **子任务数由题型决定**：机理题（A）3 步、数据题（C）4 步、运筹题（D）3 步、综合评价题（F）4 步、交叉学科（E）4~5 步、实验题（B）3~5 步。
2. **首子任务永远是「建立基础模型 / 抽象」**，末子任务永远是「敏感性 / 鲁棒性 / 验证 / 策略」。
3. **子任务间的产出即下一任务的输入**（线性衔接为主），赛题自带 Q1/Q2/Q3 子问时，子问与子任务天然对齐；子问内部再按子任务拆。

---

## 一、A 题（物理 / 机理）

推荐 **3 子任务**（题目若含 4~5 问则扩充到 5 子任务）：

| 子任务 | 职责 | 常用方法示例 |
|---|---|---|
| 1. 建立初始模型 | 识别关键变量、参数、控制方程；微分方程 / 概率 / 优化框架；简化假设孤立主现象 | 微分方程、参数估计、平衡分析 |
| 2. 约束 / 优化扩展 | 加入动力学 / 时间行为、外部约束、非线性交互；从"可解"到"贴合现实" | 数值模拟、动态规划、优化 |
| 3. 鲁棒性 / 敏感性 | 改变参数 / 初值 / 边界条件，评估传播与稳定区间 | 敏感性分析、稳定性分析、摄动法 |

> 物理可行性铁律（[model-selection.md](model-selection.md) §十一）在子任务 2 强制生效。

---

## 二、B 题（实验 / 数据分析）

推荐 **3 子任务**（含多目标 / 资源分配场景时 4~5 子任务）：

| 子任务 | 职责 |
|---|---|
| 1. 基础模型 | 构建核心动态 / 关系的初始框架（优化 / 概率 / 仿真） |
| 2. 场景应用与优化 | 跑仿真 / 数值分析，评估不同输入 / 策略的 trade-off，找最优 |
| 3. 验证与鲁棒性 | 不确定性 / 参数敏感性 / 泛化验证 |

---

## 三、C 题（数据驱动）

推荐 **4 子任务**：

| 子任务 | 职责 | 备注 |
|---|---|---|
| 1. 数据预处理 | 清洗、缺失值补全（统计 / 聚类）、归一化 / 缩放 | 降噪、去偏 |
| 2. 评分 / 分类框架 | 识别关键变量、构造指标 / 指数、量化评分或分类 | 可结合 DM/ML |
| 3. 预测建模 | 统计 / 机器学习 / 时间序列预测，历史数据回测验证 | 含 backtesting |
| 4. 敏感性 / 探索建模 | 变参数 / 约束 / 假设，量化影响，识别关键驱动 | — |

---

## 四、D 题（运筹 / 优化调度）

推荐 **3 子任务**：

| 子任务 | 职责 |
|---|---|
| 1. 构建基础模型 | 图 / 网络 / 方程抽象；定义变量、关系、约束 |
| 2. 优化 / 评估 / 自适应 | 改进算法、概率方法 / 动态规划，找最优 / 缩短时延 / 提升性能 |
| 3. 敏感性 / 鲁棒性 / 更广影响 | 变参数、外扰、多目标，识别关键阈值 |

---

## 五、E 题（交叉学科）

推荐 **4~5 子任务**：

| 子任务 | 职责 |
|---|---|
| 1. 数据采集与预处理 | 补齐、分类、归一化、离散化 |
| 2. 模型表示 | 构造指标 / 指数量化关键变量，概率 / 确定性 / 混合框架 |
| 3. 参数估计与校准 | 赋权重 / 值，优化 / 统计推断 / 层次加权 |
| 4. 模型分析 | 对照经验数据验证、参数敏感性、输出校验 |
| 5.（可选）应用与泛化 | 案例分析、场景仿真、迁移到新情境 |

---

## 六、F 题（综合评价 / 决策）

推荐 **4 子任务**：

| 子任务 | 职责 |
|---|---|
| 1. 建立量化框架 | 定义指标 / 参数 / 变量，构造模型结构（回归 / 优化 / 仿真） |
| 2. 多准则评价扩展 | 引入社会 / 经济 / 环境维度，熵权 / 统计加权量化重要性 |
| 3. 场景 / 干预评估 | 变参数、仿真不同条件，评估变动的系统影响 |
| 4. 策略建议 | 综合洞察产出可执行方案 / 指南，论述可行性 |

---

## 七、衔接与落点

- 每一子任务的**输出物**落到 `work/` 下的分析草稿（如 `analysis_q1.md`），供下一子任务与下游手消费。
- 子问 Q1/Q2/Q3 若存在依赖，按 `core/tools/state.py` 的 `qfail`/`qfix` 局部回修，不全局回退。
- 本文件只给「拆法」，不替 agent 决定具体模型——选型仍走 [model-selection.md](model-selection.md) 决策树。
