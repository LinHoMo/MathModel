# Paper Bridge —— MODEL_SPEC 到论文章节的映射契约

> 消费方：Writer（structure-planner / section-writer / consistency-checker）
> 生产方：Modeler（spec-auditor 渲染 `output/MODEL_SPEC.md`）
> 作用：把建模手的结构化产物，无损、可追溯地搬进论文，杜绝「模型换了摘要没换、数字没有脚本来源」这类隐性失败。

---

## 1. 定位与铁律

Paper Bridge 是 Modeler 与 Writer 之间唯一的**语义映射契约**。它回答一个问题：

> `MODEL_SPEC.md` 里的每一节，应该出现在论文的哪个章节？以什么形式？哪些数值必须原样搬运、哪些必须改写？

两条不可违反的底线（对应铁律 W1 / P2 / M4）：

1. **数值单一真源**：论文正文每一个计算结果数值，必须能回溯到 `figures/all_results.json`（经 `freeze_numbers.py` 冻结后由脚本判定，追溯率 ≥ `runtime.traceability_min_ratio`）。
2. **语义一致**：论文的假设、符号、边界条件、模型选型，必须与 `MODEL_SPEC.md` 一一对应，不允许在撰写阶段「重新发明」一套符号或假设。

## 2. MODEL_SPEC → 论文章节映射表

| MODEL_SPEC 章节 | 论文章节（CUMCM 主线） | 呈现形式 | 搬运规则 |
|---|---|---|---|
| 1. 问题理解 / 1.1 子问题列表 | 问题重述 + 问题分析 | 散文 + 分条 | 子问题编号沿用 Q1/Q2/Q3；「依赖」列改写为分析叙述，不照抄表格 |
| 2. 模型假设 (H1…Hn) | 模型假设 | 编号列表 + 理由 | 每条假设 + 量化评分转成「必要性说明」；删除「类型」列内部术语 |
| 3. 符号说明 | 符号说明 | 三线表 | 符号/含义/单位三列保留；「首次出现」列改写为正文引用，不进表 |
| 4. 模型选型 / 4.1 候选对比 | 模型建立（引言段） | 对比表 + 选择理由 | 候选对比表保留，但只保留读者关心的维度（优点/缺点/适用性）；「选择结论」展开为一段论证 |
| 5. 模型建立（5.1/5.2 每个子问题） | 模型建立与求解（按子问题分节） | 公式 + 推导 + 求解 + 结果 | 公式原样搬运；推导过程按「步骤」改写为连贯推导；边界条件单列 |
| 6. 代码实现要求 | 附录（代码）/ 正文一句话 | 一句话 + 附录 | 正文只写「求解采用 Python 实现，核心算法见附录」；函数表进附录或省略 |
| 7. 预期结果 | （不进论文，供验证对照） | — | 与「实际结果」对照，出入 >10% 需在模型评价中说明 |
| 8. 验证要求 | 模型检验 / 灵敏度分析 | 小节 + 图表 | 每项验证方法对应一张图/表；灵敏度分析必写（W9） |

**逆向校验**（Writer 完成后自检）：论文每个章节都能在 `MODEL_SPEC.md` 找到对应来源；反之，`MODEL_SPEC.md` 的「预期结果」若与论文「实际结果」冲突，必须回到模型评价说明，不得静默丢弃。

## 3. 数值占位符协议

### 3.1 单一真源机制（复用 `freeze_numbers.py`）

```
figures/all_results.json ──freeze──▶ work/frozen_numbers.json ──check──▶ paper/main.tex
        （Programmer 产出）          （冻结快照 + 来源哈希）        （正文数字追溯率 ≥ 90%）
```

- **冻结**：`python core/tools/freeze_numbers.py <项目> freeze` —— 把 `all_results.json` 扁平化为 `frozen_numbers.json`，记录每个数值的键路径与来源哈希。
- **校验**：`python core/tools/freeze_numbers.py <项目> check` —— 比对结果文件是否被改动，并统计论文正文数字的追溯率。

### 3.2 撰写期占位符约定

在正文尚未拿到最终数值前，禁止手写「拍脑袋」的数字。使用如下占位符，待 `all_results.json` 就绪后由 consistency-checker 统一回填：

```
[[Q1.opt_value]]      # 问题一最优值（对应 all_results.json 键路径 Q1.opt_value）
[[Q2.rmse]]           # 问题二均方根误差
[[Q3.total_time]]     # 问题三总时长
```

规则：

1. 占位符命名必须与 `all_results.json` 的键路径一致（`.` 分隔），不得自创别名。
2. 回填后立即 `freeze` + `check`，追溯率不达标则回退修正。
3. 四舍五入统一在**回填时**做一次，正文不再二次改口径（W1）。

### 3.3 数字写作规范

- 关键结果**摘要必须含具体数值**（W2/W13），且与正文同源。
- 表内数字保留有效位数一致；百分比与绝对数不混用。
- 启发式算法结果必须报告「均值 ± 标准差」（P6），不写单次最优。

## 4. 假设呈现规范

`MODEL_SPEC.md` 假设表 → 论文假设列表的转换规则：

| MODEL_SPEC 字段 | 论文呈现 |
|---|---|
| 编号 H1…Hn | 保留编号，正文统一 `H1`…`Hn` 引用 |
| 假设内容 | 原样保留（必要时润色为书面语） |
| 类型（关键/次要/简化） | **不进论文**；「关键假设」在正文额外多写一句为何关键 |
| 量化验证（评分） | 改写为「合理性说明」：定性理由 +（若有）量化证据 |
| 合理性说明 | 并入上一条 |

**禁止**：假设只罗列、不说明必要性（对应 `_negative/case-06`）。每条假设至少一句「为什么需要这条假设」与「放宽它会怎样」。

---

## 5. 符号呈现规范

`MODEL_SPEC.md` 符号表 → 论文符号表的转换规则：

1. **三列**：符号 / 含义 / 单位。删除「首次出现」列（改为正文自然引入）。
2. **全文一致**：符号必须与 `MODEL_SPEC.md` 及代码注释一致（M4，由 `symbol_registry.py` 校验），不得在撰写阶段换符号。
3. **量纲标注**：每个物理量带单位；无量纲量标注「无量纲」。
4. **排序**：按子问题或字母序排列，`\theta`、`\alpha` 等希腊字母统一斜体 `\mathit{}` 或数学环境。

---

## 6. 边界条件呈现规范

`MODEL_SPEC.md` 5.x「边界条件」→ 论文：

- 每个子问题单独列出**初始条件**与**约束条件**，编号 `(x)`，与公式连续编号不冲突。
- 边界条件必须在**求解前**写清，不能在结果处「补条件」。
- 若边界条件来自赛题数据（如附件 1 的初始状态），注明数据来源。

---

## 7. 模型评价诚实讨论模板

对应铁律 W10（模型评价必须诚实讨论缺点）。每个子问题求解后，用以下结构收尾（可合并到「模型评价」章）：

```markdown
**优点（2-3 条）**：
- （本模型真正做到的，如「解析可求解」「对小样本稳健」）

**局限（必写，≥2 条）**：
- （假设的代价，如「H3 的球形云团假设在高风速下偏差增大」）
- （方法的边界，如「差分进化不能保证全局最优，仅给出统计意义上的近似」）

**改进方向（1-2 条）**：
- （可执行的下一步，如「引入非球形云团模型」「用 MILP 求下界以衡量 DE 的间隙」）
```

**禁止**：只写优点不写缺点；用「模型较优」这类空话代替具体局限；把局限写得比优点还致命却不下修。

## 8. 反面清单（撰写前自查）

| 症状 | 根因 | 拦截 |
|---|---|---|
| 摘要数字与正文/代码不一致 | 摘要后写、口径漂移 | 摘要最后写 + freeze check |
| 第二问改模型，第三问还在引用旧结果 | 依赖未显式化 | dag-builder 的 DAG + 逆向校验 |
| 论文数字无脚本来源 | 撰写阶段重新估算 | 占位符协议 + 追溯率门禁 |
| 符号表与正文不一致 | 撰写阶段换符号 | symbol_registry 校验 |
| 假设只有罗列 | 缺必要性说明 | case-06 规则 + 假设呈现规范 |
| 结果过好（误差恒为零） | 数据泄露 / 过拟合 | `_negative/case-05` + 结果合理性检查 |
