# 负样本：论文数字无脚本来源

> 对应反模式：antipatterns.md #13「论文数字无脚本来源——在 `all_results.json` 里找不到对应记录」

## 问题切片

某赛题结论与敏感性分析一节出现这样一段：

> 经过模型求解，问题一的总成本为 452.3 万元，问题二的最优路径长度为 3187 千
> 米，问题三的综合评分前三名分别为 0.912、0.887、0.861。对运输单价做 ±10% 的
> 扰动，总成本变化不超过 3.2%，说明模型对价格参数不敏感。

但当评审打开 `figures/all_results.json` 核对时：

- `all_results.json` 里只有 `q1`、`q2` 两个顶层的粗糙值，没有 `q3` 的综合评分数组；
- 正文写的"452.3 万元"在 json 里是 `452.3487`（保留位数不同），"3187 千米"在 json 里
  是 `3186.92`，正文四舍五入后又参与了下文计算；
- "灵敏度分析 ±10% 变化不超过 3.2%"在 json 里**根本没有对应记录**，敏度扫描的结果
  没有落盘，只在论文阶段手写了一句结论。

## 失分归因

1. **命中 #13 原文"在 all_results.json 里找不到对应记录"**：q3 评分、灵敏度 3.2% 这两组
   数字在 `all_results.json` 中均无来源，属于论文阶段**重新估算/凭空写入**的数字，
   违反铁律 W1 / P2「所有数值可追溯到 `figures/all_results.json`」。——严重度 `blocking`
   （数字无来源是 weakness-hunter 明确列出的阻塞项示例）。
2. **数字口径不一致**（452.3 vs 452.3487、3187 vs 3186.92）连带命中 **#18「数字有效位
   不合理」**与 **#14「修 bug 后论文仍用旧数字」的风险**：正文对 json 值二次四舍五入后
   再用，导致读者无法复算，且改一处不改另一处必出 #14。
3. **命中 #17「灵敏度分析流于形式」的变体**：敏度结论"3.2%"没有落盘记录，无法验证
   "是否真的重新完整求解"，与 numeric-edge-cases #10「假扰动」同源。

## 正确做法

| 错误 | 修正 |
|---|---|
| 正文手写"452.3 万元 / 3187 千米 / 前三名 0.912…" | 所有数字从 `all_results.json` 读取后**原值**呈现（或按统一保留规则读同一字段），论文里每个数字都能在 json 里按 key 找到同值记录 |
| 敏度"3.2%"只写了结论 | 敏度扫描结果落到 `all_results.json`（或 `result_validation.json`），每个扫描点记录"实际输入 → 实际输出"，正文引用该字段 |
| q3 评分无落盘 | Programmer 手必须产出 q3 的评分数组并写入 json；Writer 手只需引用，不得重算 |
| 正文数字与 json 位数不同 | 统一一位保留规则（如"正文与 json 均保留 4 位有效数字，逗号分隔千分位只作排版"），或正文只展示、计算用全精度 |

可转成 revision-planner 验收标准：对论文中每个数值 `grep` 出来，再在 `all_results.json`
中 `grep` 同值，全部命中即通过；敏度节必须在 json 的 `sensitivity` 数组中存在对应记录。

## 涉及阶段

- **产生环节**：
  - Programmer 手 `result-verifier` / `code-implementer`（求解结果未完整落盘到
    `all_results.json`，或落盘字段不全）；
  - Writer 手 `section-writer`（写作阶段擅自四舍五入、甚至补充了 json 里没有的数字）。
- **检出环节**：
  - Writer 手 `consistency-checker`（L4 论文-代码数值一致性，本应在此挡下，却漏检）；
  - Reviewer 手 `weakness-hunter`（扫描命中 `antipatterns#13`，严重度 blocking）。
- **回退建议**：`consistency-checker` 未挡下 → 先让其重跑；数字无来源 → 回 Programmer 手
  补落盘（`result-verifier`）后再让 Writer 手按 json 重写该节（`section-writer`）。
