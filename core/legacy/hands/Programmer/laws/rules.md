# Programmer Laws

## 六层防御体系

本角色嵌入六层防御体系，每条铁律对应防御层次：

| 铁律 | 防御层次 | 执行机制 |
|------|---------|---------|
| P1 | L5 运行时护栏 | 代码必须包含np.random.seed(42) |
| P2 | L1 结构化输出 | results_ledger必须包含problem_N结果 |
| P3 | L3 过程验证 | ProcessVerifier检查文件路径 |
| P4 | L3 过程验证 | ProcessVerifier检查docstring |
| P5 | L5 运行时护栏 | 代码必须包含try-except |
| P6 | L2 工具调用 | 多次运行函数返回统计结果 |
| P7 | L2 工具调用 | 优化函数先检查可行解 |
| P8 | L5 运行时护栏 | 数据加载必须检查编码/列名/缺失值 |
| P9 | L1 结构化输出 | CODE_DELIVERABLES必须包含运行说明 |
| P10 | L4 异构验证 | ResultVerifier 逐条检查约束 |
| P11 | L5 运行时护栏 | Guardrails 检查超时配置 |
| P12 | L3 过程验证 | StageGate 检查修复轮数 |

## 铁律（不可违反）

### P1: 代码必须设置随机种子，保证可复现
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - 只 seed 了 numpy，没 seed random/torch/scipy，多库随机源未统一，结果仍不可复现
  - 种子设在函数内部，每次调用函数都重置种子导致"随机"序列重复
  - 多进程/多线程未设种子，各 worker 结果不可复现
- 必须包含 `np.random.seed(42)` 或等效设置
- 随机算法要多次独立运行（≥5次），报告均值和标准差
- 保存环境、输入、参数、代码入口和输出哈希

### P2: 所有数值必须可追溯到 figures/all_results.json
- **防御层次**: L1 结构化输出
- **典型反例**:
  - 论文写 0.832 但 all_results.json 是 0.8317，四舍五入口径不一致
  - 账本缺单位（写 12.5 不写 km/h），下游 Writer 无法判断量纲
  - 账本记录了结果但漏记计算参数与入口，下游无法复现
- 所有论文会引用的数值必须能追溯到 `figures/all_results.json`
- 不要在论文阶段重新估算或换一套四舍五入口径
- 结果文件应记录：关键参数、核心数值、约束检查、灵敏度或鲁棒性结果

### P3: 代码文件必须放在 code/ 目录，图表放在 figures/，表格放在 tables/
- **防御层次**: L3 过程验证
- **典型反例**:
  - `savefig("x.png")` 无目录前缀，文件落在项目根目录污染根目录
  - `result.xlsx` 放 figures/（应放 tables/），目录分类错乱
  - 创建空 results/ 目录占位但无产物，违反"空目录不得创建"
- 代码中所有文件保存操作必须使用目录前缀的相对路径
- 不得直接写文件名
- 不得创建无产物的空目录

### P4: 每个代码文件必须有模块docstring和函数docstring
- **防御层次**: L3 过程验证
- **典型反例**:
  - 函数无 docstring，下游不知道参数含义与返回值
  - docstring 只写"计算"不写参数、返回值、异常，信息量为零
  - 模块无 docstring，不知道整个文件用途，维护困难
- 模块级docstring说明文件用途
- 函数docstring说明参数、返回值、异常
- 关键代码块添加注释

### P5: 必须处理异常情况（文件不存在、数据格式错误等）
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - 裸 `except:` 吞掉所有异常包括 KeyboardInterrupt，错误被静默
  - except 后直接 pass 无错误信息，调试时无法定位问题
  - 文件读取不检查存在性，文件缺失直接崩溃无友好提示
- try-except捕获异常
- 提供有意义的错误信息
- 优雅降级处理

### P6: 启发式算法必须多次运行（≥5次），报告均值和标准差
- **防御层次**: L2 工具调用
- **典型反例**:
  - 启发式只跑 1 次报"最优"，无稳定性验证，结果可能是局部最优
  - 跑 5 次但只报均值不报标准差，掩盖算法不稳定
  - CV>10% 不增加种群或迭代次数，直接交付不可靠结果
- 随机算法结果具有随机性
- 多次运行评估稳定性
- 若标准差/均值 > 10%，说明优化不稳定，须增加种群或迭代次数

### P7: 优化问题必须先保证可行解，再优化目标值
- **防御层次**: L2 工具调用
- **典型反例**:
  - 硬约束报"无解"就停止，不尝试软惩罚或松弛，问题未解决
  - 优化变量上界随意设 1000（超出物理意义），返回物理不可行解
  - 不检查求解器 success 标志，盲目信任返回值，解可能违反约束
- 硬约束过多导致可行域为空时，不得直接报"无解"
- 改为软惩罚：f = 原目标 + λ·Σ(max(0, -约束)²)
- 优化变量上界必须等于物理可行域上界

### P8: 数据读取后必须检查编码、列名、形状、缺失值
- **防御层次**: L5 运行时护栏
- **典型反例**:
  - 不检查编码直接 read_csv，中文列名乱码或报 UnicodeDecodeError
  - 不检查缺失值，NaN 参与运算产生静默错误（如 mean() 返回 NaN）
  - 列名含中文空格/特殊字符未处理，后续 df["列名"] 报 KeyError
- 检查文件编码（UTF-8/GBK等）
- 检查列名是否正确
- 检查数据形状
- 检查缺失值和异常值

### P9: CODE_DELIVERABLES.md 必须包含所有代码文件的运行说明
- **防御层次**: L1 结构化输出
- **典型反例**:
  - CODE_DELIVERABLES 无运行命令，评委不知道怎么跑代码
  - 依赖列表与实际 import 不符（漏写或写多余），环境无法复现
  - 无预计运行时间，评委无法判断超时是否正常
- 每个代码文件的功能说明
- 运行命令
- 预计运行时间
- 依赖包列表

## 编程防错速查表

> 从历年真题踩坑逆向整理，沉淀至本章编程防错速查表，覆盖 scipy 与 numpy 常见错误。编码阶段逐条核对，命中即修正。

### scipy 防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| minimize 当最大化 | 直接把最大化目标传给 minimize，结果取了最小值 | `scipy.optimize.minimize` 只做最小化；最大化时目标取负，结果记录还原真实值 |
| 不等式约束方向错 | 容量约束 x≤C 写成 fun(x)=x-C 期望≥0 | scipy 约束方向是 `fun(x) >= 0`；x≤C 应转化为 `C-x >= 0` |
| 盲信 success 标志 | 求解器 success=True 但解实际违反约束 | 最优解必须重新代入所有约束函数检查可行性 |
| 整数变量停留连续 | MIP 松弛后直接取连续解不重验 | 整数变量取整后必须重新验证可行性与目标值 |

### 优化防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 目标函数不连续 | 分段常数目标（如"遮蔽时长"）梯度处处为 0，优化器停滞 | 改连续代理目标（如"最小化云团到视线距离"） |
| 硬约束致可行域空 | 求解器报无解直接放弃，不尝试松弛 | 改软惩罚：f = 原目标 + λ·Σ(max(0, -约束)²) |
| 物理上界缺失 | 变量上界随意设大值（如 1e6），返回物理不可行解 | 上界 = 物理可行域上界，不得超出物理意义 |
| 单起点不稳定 | 只跑一次结果差但无法判断是算法问题还是初值问题 | 多起点≥5 次，报告均值/标准差/最优，CV>10% 增加种群 |

### 数据防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 编码错误 | read_csv 中文乱码或报 UnicodeDecodeError | 先尝试 utf-8，失败回退 gbk/latin1；或用 chardet 检测 |
| 列名问题 | 列名含空格/中文/特殊字符，df["列名"] 报 KeyError | 读取后 `df.columns = df.columns.str.strip()`；重命名为英文 |
| 形状不符 | 期望二维数组实际一维，矩阵运算报形状错误 | 读取后 `assert df.shape == (期望行, 期望列)` |
| 缺失值 | NaN 参与运算静默错误（mean() 返回 NaN） | `df.isnull().sum()` 检查；按策略填充（均值/中位数）或删除 |
| 异常值 | 离群点拉偏模型，回归系数失真 | `df.describe()` 看分布；IQR 或 3σ 检测，按业务判断保留或剔除 |

### 机器学习防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 过拟合 | 训练集精度高测试集骤降 | 训练/验证/测试三分；测试集只评估最终模型，不参与调参 |
| 类别不平衡 | 准确率 99% 但少数类全错 | 改用 F1、AUC-ROC；过采样（SMOTE）或欠采样 |
| scaler fit 错误 | 在全数据 fit scaler 再划分，数据泄露 | scaler 只在训练集 fit，再 transform 验证集/测试集 |
| 时序划分错误 | 时序数据用随机 K-Fold，未来信息泄露 | 时序用 TimeSeriesSplit，按时间顺序划分；类别编码在划分后做 |

### 目录与文件防错速查表

| 错误类型 | 典型表现 | 防错方法 |
|---------|---------|---------|
| 文件落根目录 | `savefig("x.png")` 无目录前缀，污染项目根目录 | 必须带目录前缀：`savefig("figures/x.png")` |
| 目录分类错乱 | result.xlsx 放 figures/（应放 tables/） | 表格→tables/，图表→figures/，代码→code/ |
| 空目录占位 | 创建空 results/ 目录但无产物 | 有产物时才创建目录；不得创建空目录占位 |

## 铁律新增（对标 mmagent-codex-main）

### P10: 约束重验证（最优解必须重新代入所有约束）
- **防御层次**: L4 异构验证
- **执行机制**: ResultVerifier 逐条检查约束
- **规则**:
  1. 优化问题求解后，必须将最优解重新代入所有约束条件
  2. 输出每条约束的取值、边界值、松弛量（slack）、是否活跃（active）
  3. 若任一约束违反（超出容差），标记 FAIL 并回退
  4. 约束检查结果记录在 all_results.json 的 constraint_verification 字段
- **违反后果**: 未做约束重验证的结果不得进入 Writer 手

### P11: 求解器超时分级（按问题规模设超时阈值）
- **防御层次**: L5 运行时护栏
- **执行机制**: Guardrails 检查超时配置
- **规则**:
  1. 求解器超时按变量数分级：<100 变量 = 300s，100-1000 变量 = 600s，>1000 变量 = 1200s
  2. 超时阈值从 env/code.solver_timeout_* 读取，不得硬编码
  3. 超时后必须记录当前最优解与 gap，不得丢弃
  4. 超时发生必须在 CODE_DELIVERABLES 中说明
- **违反后果**: 未设置超时或超时配置不合理的代码不得运行

### P12: 修复轮数上限（单子问题修复 ≤3 轮，超限回退）
- **防御层次**: L3 过程验证
- **执行机制**: StageGate 检查修复轮数
- **规则**:
  1. 每个子问题的代码修复轮数上限为 3 轮（从 env/code.max_fix_rounds 读取）
  2. 3 轮内无法通过测试的，必须回退到 Modeler 手重新建模，而非继续修补
  3. 每轮修复必须记录修复内容、修复前后测试结果
  4. 修复轮数超限时，StageGate 返回 FAIL，触发回退流程
- **违反后果**: 超过 3 轮仍不通过的代码不得进入 Writer 手，必须回退 Modeler
