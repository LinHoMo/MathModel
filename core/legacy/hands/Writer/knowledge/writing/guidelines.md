# 学术写作指南

> 本文件提供学术论文写作的核心原则和规范，作为 SKILL.md 的写作参考。

---

## 叙事原则

### 一句话贡献测试

论文的核心贡献必须能用一句话表述：

- "We prove that X converges under assumption Y."
- "We show that method A improves B by 15% on benchmark C."
- "We identify failure mode D and propose mechanism E that removes it."

如果写不出来，说明 framing 还没收敛。

### What-Why-So What 结构

引言结束时，读者应清楚理解：

- **The What**: 论文的 1-3 个具体贡献
- **The Why**: 支撑这些贡献的证据
- **The So What**: 为什么社区应该关心

### 审稿人阅读顺序

大多数审稿人的阅读顺序：Title → Abstract → Introduction → Figures (especially Figure 1) → The rest

**写作启示**: 把主要精力投入到标题、摘要、引言和 hero figure。如果前两页不清楚，后面的精彩可能永远不会被看到。

## 图文交织规则

### 图前引导

每张图/表前需要 1-2 句引导文字，说明为什么读者应该看它（不只是"如图所示"）。

如果图/表很大（占半页以上），引导文字必须至少 3-5 句。

### 图后分析

每张图/表后需要 3-5 句分析：

1. 数据解读：关键数字/趋势是什么
2. 对比/原因分析：与其他方法/组/期望的对比
3. 结论推断：这个结果意味着什么

### 连续图表规则

连续两张图/表之间必须有至少一个完整段落（≥5 行文字）。绝对禁止两张图/表连续出现中间没有分析文字。

### 图表是论据不是主语

**禁止模式**（AI 典型痕迹）：
```
图3展示了三种算法的收敛曲线。从图中可以看出，遗传算法收敛最快。
图4给出了灵敏度分析的结果。由图可知，参数α对结果影响最大。
```

**正确写法**（论点驱动）：
```
算法选择的关键在于收敛效率与解质量的平衡。在相同迭代次数下，
遗传算法在第15代即趋于稳定，而模拟退火需要约40次迭代才能达到
相近精度（图3）。考虑到竞赛时间约束，本文最终采用遗传算法求解。
```

**核心原则**：
- 段落不能以"图X展示了"、"如图X所示"开头
- 图表引用优先用括号旁注形式 `（图X）`
- 每个图表的分析段落必须包含：数值解读 + 对比分析 + 结论推断

## 段落结构

### 基本要求

- 每段 ≥3 句。不要出现 1-2 句的微段落。
- 连续段落不能以相同短语开头。
- 正文中禁止使用 `\begin{itemize}` 和 `\begin{enumerate}` 列表（AI 写作痕迹）。

### 过渡词使用

用自然过渡替代机械排比：
- "首先...其次...最后..." → 改用"与此同时"、"另一方面"、"在此基础上"
- "综上所述" → 直接进入结论
- "众所周知" → 删除整句开头

## LaTeX 写作要点

### 公式格式

- 块级公式：`$$` 必须单独占一行，前后各空一行
- 行内公式：用 `$...$`，内部避免用 `_` 做下标时与 markdown 斜体冲突
- `\begin{aligned}` 等多行环境必须放在 `$$...$$` 块级公式中

### 引用格式

- 图表引用：`图~\ref{fig:xxx}`（波浪号防止换行）
- 文献引用（GB/T 7714 顺序编码制，竞赛论文强制）：正文用 `\cite{key}`，由导言区 `\usepackage[numbers,square,super]{natbib}` + 文末 `\bibliographystyle{gbt7714-numerical}` 渲染为右上角上标 `[n]`；**禁止** `\citep{}`/`\citet{}`/`\citeauthor{}`/`\citeyear{}` 等作者—年份格式
- 连续引用：`\cite{key1,key2,key3}`（合并，不要分开）
- 引用编号必须按正文首次出现顺序**严格递增**（1,2,3,…），写完逐段扫描确认无编号跳跃或回退

### 表格格式

- 宽表格（≥6 列）：用 `\resizebox{\textwidth}{!}{...}`
- 超过 12 行的结果表：正文只放前 3 行 + `$\vdots$` + 后 3 行，完整表放附录
- 三线表：`\toprule`、`\midrule`、`\bottomrule`

### 图片格式

- 路径：`../figures/xxx.pdf`（相对于 paper/ 目录）
- 宽度：单张 `width=0.9\textwidth`，双栏并排 `width=0.48\textwidth`
- Float specifier：用 `[H]`（需要 `\usepackage{float}`）
- Caption：简短（≤15 中文字或 ≤10 英文词），详细描述放正文

## 禁止事项

### 正文中禁止出现

- 内部文件名、脚本名、临时目录
- "由 AI 生成"等过程痕迹
- "参赛者"、"参赛队伍"、"我们团队" → 用"本文"
- "数据驱动"、"可解释建模"等从 SKILL 指令复制的原则性描述

### 常见写作错误

- 假设没有在正文建模处引用
- 结论只给数值，不解释含义
- 图表出现但正文没有引导和解释
- 公式符号首次出现处没有定义
- 参考文献是捏造的
- 摘要和正文数值不一致

## 摘要写作

### 五句话公式

1. 你实现了什么
2. 为什么问题重要且困难
3. 你如何处理的
4. 什么证据支撑了你的主张
5. 读者应该记住什么数字/结果/保证

### 要点

- 每个子问题必须覆盖：方法 + 模型 + 关键结果（含数值）
- 不要出现复杂公式和表格
- 不要只重述题目
- 不要用"我们认为……""本文将……"等空泛表述
- 应最后撰写（内容全部确定后）
