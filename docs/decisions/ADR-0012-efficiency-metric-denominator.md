# ADR-0012: 效率统计口径以题面定义为准，跨实现比较前必须先归一

- Status / 状态：Accepted
- Date / 日期：2026-09-11
- Context / 上下文：

  2026 CUMCM B 题要求报告「被清除干扰源个数比例」与「平均定位清除时间」两个统计量
  （`projects/cumcm2026b/inputs/problem.txt:9`）。题面本身**只给名称不给公式**；
  精确口径写在附件材料与竞赛论文的实跑记录表中，为：

  > 平均定位清除时间 = 定位清除总时间 / 已清除干扰源个数，
  > 总时间含移动、频道切换、检测、光学定位与清除。

  而本项目 `projects/cumcm2026b/artifacts/code/solve_b.py` / `solve_b_http.py` 的实现
  采用的是**逐源口径**：`mean_locate_clear_time_s = mean(该源清除时刻 − 该源首次探测时刻)`
  （见 `dog_strategy_http()` 的 `per_src` 计算）。两个口径同名不同义：

  | 实现 | 字段 | 口径 | Q4 实测 |
  |---|---|---|---|
  | 本项目 | `mean_locate_clear_time_s` | 逐源（清除−首探），含并行等待 | 17514 s（优化前） |
  | 对比组 b_win | `avg_locate_clear_s` | 总时间 / 清除数 | 701.9 s（=10528.1/15） |

  对同一份模型，两种口径相差数量级：拿逐源口径直接对比基准的摊薄口径，会得出
  「慢 25 倍」的结论；而归一到同一口径后，真实差距约为 2 倍。**错误的口径会把
  优化方向引向错误的目标线**——这正是本 ADR 要固化下来的教训。

- Decision / 决策：

  1. **统计口径的真源是题面/附件原文，不是实现者自选的公式。** 报告任何竞赛统计量前，
     先从题面原文（含附件、评分表模板）定位其定义；题面未给公式时，采用该题官方
     实跑记录模板给出的口径。
  2. **跨实现比较前必须先把双方归一到同一口径。** 任何「我们比 X 慢 N 倍 / 快 N 倍」
     的结论，必须先声明双方口径并做归一换算，否则不得写入交付文档。
  3. **实现须同时报告两个口径**（逐源口径与摊薄口径），二者分别回答不同问题：
     逐源口径衡量「单个源从被发现到被清除要多久」（受并行/串行影响），
     摊薄口径即题面统计量（衡量「清完全部源平均每个耗多少」）。命名上不得混用。
  4. **本文档影响的判据**：cumcm2026b 的目标线（平均定位清除时间）统一按摊薄口径
     对齐，与对比基准 b_win 的 `avg_locate_clear_s` 可直接比较。

- Consequences / 后果：

  正面：
  - 消除了「同名统计量、不同口径」导致的结论漂移；优化目标线有了唯一、可复核的定义。
  - 归一后差距从「25 倍」收敛到「2 倍」，把优化从「推倒重来」拉回「定向调优」，
    避免了基于虚假差距的过度工程。

  负面 / 约束：
  - 每个竞赛实例的结果台账需同时维护两套口径的字段，并要求文档引用时标注口径；
  - 逐源口径字段名 `mean_locate_clear_time_s` 与题面统计量同名，存在再次误引风险，
    引用时必须以「逐源」/「摊薄」限定词显式区分。
  - 后续若官方给出更明确的公式，以官方为准，本 ADR 相应更新。

- Evidence / 证据：

  - 口径定义（官方）：`对比\b_win\b\表1_实跑记录模板.csv` 说明第 3 条
    「平均定位清除时间 = 定位清除总时间 / 已清除干扰源个数（题面统计口径），
    总时间含移动、频道切换、检测、光学定位与清除」。
  - 对比组实测：`对比\b_win\b\data\official_report.json` →
    `locate_clear_total_s = 10528.1`、`n_cleared = 15`、`avg_locate_clear_s = 701.9`
    （= 10528.1 / 15，摊薄口径）。
  - 本项目口径（逐源）：`projects/cumcm2026b/artifacts/code/solve_b_http.py`
    `dog_strategy_http()` 的 `per_src = [clear_time[ch] − det_time[ch] ...]`。
  - 两口径实测差：本项目 Q4 逐源口径 17514 s vs 摊薄口径 1690 s（优化前，
    `projects/cumcm2026b/artifacts/results/resultB_http_mock.json` 与
    `all_results.json:summary.problem4`）。
