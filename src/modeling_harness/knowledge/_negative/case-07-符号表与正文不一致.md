# 负样本：符号表与正文不一致

> 对应反模式：antipatterns.md #10「符号表与正文不一致——定义了没用，或用了没定义」

## 问题切片

某论文"符号说明"一节给出如下符号表：

| 符号 | 含义 |
|---|---|
| $N$ | 节点集合 |
| $d_{ij}$ | 节点 $i$ 到 $j$ 的距离 |
| $T$ | 规划周期 |
| $x_{ij}^{t}$ | 时刻 $t$ 车辆是否从 $i$ 到 $j$ |

但正文建模时：
- 目标函数里出现的是 $\sum_{i}\sum_{j} c_{ij} x_{ij}$，符号 $x_{ij}$ 和 $c_{ij}$ **正文用了、
  符号表没定义**；
- 约束里冒出一个 $Q$（车辆容量），符号表也没有；
- 符号表里定义了 $T$（规划周期）和 $x_{ij}^{t}$（带时间上标），正文却**从头到尾没用
  这两个符号**，正文通篇的决策变量是 $x_{ij}$（不带 $t$）。

一句话：符号表写了一套，正文写的是另一套，两套只在名字上"有点像"。

## 失分归因

1. **命中 #10 原文"符号表与正文不一致——定义了没用，或用了没定义"**：本例同时踩了
   两个方向——`T`、`x_{ij}^{t}` 是"定义了没用"，`c_{ij}`、`Q` 是"用了没定义"。
   评委只需对着符号表和正文各扫一遍即可抓包，是最容易被机器与人都能检出的硬伤。
   ——严重度 `major`。
2. 直接违反本库铁律（schema / 契约 / 追溯）下 `symbol_registry` 类检查的预期：
   符号表应能**闭合**——正文每个符号都能在表里找到，表里每个符号都被正文引用。
   不闭合即契约破坏。
3. 连带 **#11「量纲前后矛盾」** 的高风险：符号定义脱节后，同一符号在公式间含义漂移
   的概率大增（如 $x_{ij}$ 一会是 0-1 变量、一会是流量），是后续数值错误温床。

## 正确做法

| 错误 | 修正 |
|---|---|
| 符号表定义 $T$、$x_{ij}^{t}$ 却不用 | 删掉正文不用的符号；若 $x_{ij}^{t}$ 确是有时间维度的决策变量、只是被简化成 $x_{ij}$，则显式声明"$\forall t$ 省略上标，下同" |
| 正文用了 $c_{ij}$、$Q$ 却不定义 | 在符号表补 $c_{ij}$（单位距离成本）、$Q$（车辆容量）及单位 |
| 两套符号各写各的 | 建模后跑一次符号闭合检查：`正文出现的每个数学符号 ∈ 符号表` 且 `符号表每个符号被正文引用 ≥1 次`，两边对不上的逐一修正 |

可转成 revision-planner 验收标准：用脚本提取正文 LaTeX 数学模式中的符号与符号表比对，
两侧都闭合即通过（可对标 `core/validators/modules/symbol_registry.py` 的检查逻辑）。

## 涉及阶段

- **产生环节**：
  - Modeler 手 `model-builder`（建模时符号定义与公式脱节，改公式忘了同步符号表）；
  - Modeler 手 `spec-auditor`（L5+L6 应做符号/契约审计，若漏检即失职）。
- **检出环节**：
  - Writer 手 `consistency-checker`（L4 论文内部一致性，正文-符号表闭合应是必查项）；
  - Reviewer 手 `weakness-hunter`（扫描命中 `antipatterns#10`，严重度 major）。
- **回退建议**：符号是共享前提，应回 `model-builder` 统一符号表并重审公式，小范围
  （仅补 2 个符号定义）可只回 `section-writer` 改符号表那一节。
